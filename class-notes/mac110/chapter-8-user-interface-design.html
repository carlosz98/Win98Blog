Chapter 8: User Interface Design

Phase 3, Systems Design. Design turns the logical model into a physical model. It starts with the user interface, because to users the interface is the system. Human-computer interaction (HCI) studies how people and computers work together; a GUI uses visual objects to do it.

User-centered design principles: understand the business, maximize graphic effectiveness, think like a user, use models and prototypes, focus on usability, invite feedback, document everything.

Eight guidelines for the interface:

  1. Make it transparent (users barely notice it).

  2. Easy to learn and use.

  3. Enhance user productivity.

  4. Make it easy to get help or correct errors.

  5. Minimize input data problems.

  6. Provide feedback.

  7. Create an attractive layout and design.

  8. Use familiar terms and images.

Controls: menu bars, toolbars, drop-down list boxes, dialog boxes, toggle buttons, list boxes, option (radio) buttons, check boxes and command buttons. A main switchboard is a graphical main menu.

Three report types:

ReportShowsExample
DetailOne or more lines for every recordEvery order today
ExceptionOnly records that meet a special conditionItems below the reorder point
SummaryTotals only, for managersSales by region

Report parts: a control field controls how records are grouped; a control break happens when its value changes, triggering subtotals. Reports have report, page and group headers and footers. Output can also be web pages, email, audio, instant messages and podcasts.

Source document zones (top to bottom): heading, control, instruction, body, totals, and authorization.

Input design: data capture identifies and records source data; data entry converts it to computer-readable form. Batch input collects data and processes it together; online input handles it immediately (often source data automation, like barcode scanners). Reduce errors with an input mask (a template allowing only certain characters) and validation rules:

  • Sequence check: data in order (invoice numbers).

  • Existence check: required fields are filled in.

  • Data type check: numbers where numbers belong.

  • Range and limit check: within a minimum and maximum.

  • Reasonableness check: flags values that are possible but unlikely.

  • Validity check: the value exists (a real customer number), also called referential integrity in a database.

  • Combination check: two fields make sense together.

  • Batch controls: totals to verify a batch was entered correctly.

Security and control: output control protects reports and blocks unauthorized ports and devices. Input control uses audit trails, encryption, passwords, data security and access levels.

Likely test points

  • Detail vs. exception vs. summary report.

  • Name the validation checks and match one to a scenario.

  • The six zones of a source document.

  • Batch vs. online input; data capture vs. data entry.

  • The eight interface guidelines (be able to name several).

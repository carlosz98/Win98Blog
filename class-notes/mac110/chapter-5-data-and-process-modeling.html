Chapter 5: Data and Process Modeling

Phase 2, Systems Analysis. Structured analysis builds a logical model (what the system does, not how) using three tools: data flow diagrams (DFDs), a data dictionary, and process descriptions.

The four DFD symbols (Gane and Sarson set, used in the book; Yourdon is the other common set):

SymbolGane and Sarson shapeMeaningNaming
ProcessRectangle with rounded cornersTransforms input data into outputVerb + noun (APPLY PAYMENT)
Data flowLine with an arrowheadData moving between partsSingular noun (INVOICE)
Data storeFlat rectangle open on the rightData at restPlural noun (STUDENTS)
External entitySquareA person, group or system outside the boundary that sends or receives dataSingular noun (CUSTOMER)

Three process errors (logically impossible, a favorite test item):

  • Black hole: a process with inputs but no outputs.

  • Spontaneous generation (a miracle): a process with outputs but no inputs.

  • Gray hole: inputs that cannot possibly produce the output shown.

DFD rules: data cannot flow directly between two entities, two data stores, or an entity and a data store without a process in between. A diverging data flow splits one flow to several destinations.

Leveling, the DFD pyramid:

  1. Context diagram: the whole system as one process (numbered 0) with its external entities. It shows scope, not internals, and no data stores.

  2. Diagram 0: the context process exploded into the major processes (1, 2, 3...), data stores and flows.

  3. Lower-level diagrams: each process exploded again (3.1, 3.2...), by partitioning, until you reach functional primitives, which are not broken down further and get a process description.

Read it top down: the context diagram's single process explodes into Diagram 0, and any process there can explode again until it reaches functional primitives.

Balancing means the inputs and outputs of a parent process match those of its child diagram. That keeps the set of DFDs consistent.

Data dictionary (also called a data repository): the central documentation of every data element, data flow, data store, process, external entity and record. For each data element it lists name, alias, type and length, default value, validity rules, source, and security.

Process descriptions document the logic of each functional primitive:

  • Structured English: a subset of English built from sequence, selection (IF, THEN, ELSE) and iteration (loops). It resembles pseudocode.

  • Decision table: conditions and outcomes in a grid; with n yes/no conditions there are 2^n rules. Simplify by combining rules where a condition does not matter.

  • Decision tree: the same logic drawn as branches read left to right.

Logical vs. physical models: a logical model shows what the system must do; a physical model shows how it will be built. The four-model approach builds a physical model of the current system, a logical model of the current system, a logical model of the new system, then a physical model of the new system. It is thorough but takes time.

Likely test points

  • Name and draw the four DFD symbols and their naming rules.

  • Spot a black hole, spontaneous generation or gray hole.

  • Context diagram vs. Diagram 0; what leveling and balancing mean.

  • Build a decision table (count rules as 2^n) or a decision tree from a short scenario.

  • Logical vs. physical model; the four-model approach.

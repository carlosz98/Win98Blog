Topic 1: CRUD operations and SQL

SQL rules to remember:

  • Keywords (SELECT, FROM, WHERE) are written in capitals by habit; SQL does not require it.

  • Text values go in single quotes: 'Ana'. Numbers do not: 3.60.

  • Each statement ends with ;.

  • = in SQL compares (there is no ==).

Almost every app is CRUD: sign up (Create), view your profile (Read), edit it (Update), delete your account (Delete).

Create in CRUD is not CREATE TABLE. CREATE TABLE builds the empty table once. The "C" in CRUD means adding rows with INSERT.

INSERT INTO students (first_name, last_name, major, gpa)
VALUES ('Ana', 'Lopez', 'Computer Science', 3.60);

INSERT INTO students (first_name, last_name, major, gpa) VALUES
  ('Ben', 'Kim', 'Math', 3.10),

  • The first list names the columns; VALUES gives the data in the same order.

  • student_id is left out because AUTO_INCREMENT fills it in.

R: Read (SELECT)

SELECT * FROM students;

Output:

student_idfirst_namelast_namemajorgpa

* means "all columns". The ways to narrow a read:

QueryOutput
SELECT first_name, gpa FROM students WHERE major = 'Computer Science';Ana 3.60, Carla 3.85
SELECT first_name, gpa FROM students ORDER BY gpa DESC;Carla 3.85, Ana 3.60, Ben 3.10, Dev 2.90
SELECT * FROM students WHERE last_name LIKE 'L%';Only Ana Lopez (% = any characters after L)
SELECT first_name FROM students ORDER BY gpa DESC LIMIT 2;Carla, Ana (the top 2)
SELECT COUNT(*) AS total FROM students;total = 4

  • WHERE filters rows. ORDER BY ... DESC sorts high to low (ASC, the default, is low to high).

  • LIKE matches a pattern. LIMIT caps the number of rows. COUNT(*) counts rows, and AS names the result column.

U: Update (UPDATE)

UPDATE students
SET major = 'Data Science', gpa = 3.40
WHERE student_id = 2;

Output: 1 row affected. Ben's row is now:

student_idfirst_namelast_namemajorgpa
2BenKimData Science3.40

D: Delete (DELETE)

DELETE FROM students WHERE student_id = 4;

Output: 1 row affected. The table now:

student_idfirst_namelast_namemajorgpa
1AnaLopezComputer Science3.60
2BenKimData Science3.40
3CarlaDiazComputer Science3.85

If you insert a new student now ('Eva', 'Ruiz', 'Math', 3.70), she gets student_id 5, not 4. AUTO_INCREMENT never reuses a deleted number.

The most important rule: never run UPDATE or DELETE without WHERE. DELETE FROM students; deletes every row, and UPDATE students SET gpa = 4.0; changes every student. Run a SELECT with the same WHERE first to see which rows you are about to change.

Relationships between tables (for the ERD)

TypeMeaningExampleHow it's built
One-to-one (1:1)One row matches exactly one rowOne user has one host profileFK with UNIQUE in one table
One-to-many (1:N)One row matches many rowsOne user writes many commentsFK in the "many" table
Many-to-many (N:M)Many rows match many rows, both waysA playlist has many songs, and a song can be in many playlistsA junction table with two FKs

Why many-to-many needs a third table: a playlist can't keep its songs in one column, because one column holds one value. So a junction table stores one row per link:

CREATE TABLE playlist_songs (
  playlist_id INT,
  song_id INT,
  PRIMARY KEY (playlist_id, song_id),
  FOREIGN KEY (playlist_id) REFERENCES playlists(playlist_id),
  FOREIGN KEY (song_id) REFERENCES songs(song_id)
);

INSERT INTO playlist_songs VALUES (1,1), (1,2), (2,2), (2,3);
playlist_idsong_id
1 (Road Trip)1 (Song A)
1 (Road Trip)2 (Song B)
2 (Sunday Morning)2 (Song B)
2 (Sunday Morning)3 (Song C)

Song B is in both playlists, and each playlist has two songs: that's many-to-many.

  • PRIMARY KEY (playlist_id, song_id) is a composite key: the pair must be unique, so the same song can't be added to the same playlist twice.

  • To read it back, JOIN the three tables:

SELECT p.name AS playlist, s.title AS song
FROM playlists p
JOIN playlist_songs ps ON p.playlist_id = ps.playlist_id
JOIN songs s ON s.song_id = ps.song_id
ORDER BY p.name, s.title;

Output (tested):

playlistsong
Road TripSong A
Road TripSong B
Sunday MorningSong B
Sunday MorningSong C

p, ps and s are short names (aliases) for the tables, and ON says which columns must match.

MySQL, MySQLi and PDO

  • MySQL is the database server (in XAMPP, the "MySQL" button). PHP sends it queries (SQL statements) and gets results back.

  • PHP has two ways to talk to it: MySQLi (MySQL only) and PDO (works with many databases).

  • MySQLi comes in two styles. This class uses MySQLi procedural (functions like mysqli_query($conn, $sql)).

JobProcedural (this class)Object-oriented (same thing)
Connectmysqli_connect($s, $u, $p, $db)new mysqli($s, $u, $p, $db)
Connection errormysqli_connect_error()$conn->connect_error
Run a querymysqli_query($conn, $sql)$conn->query($sql)
Query errormysqli_error($conn)$conn->error
Rows in a resultmysqli_num_rows($result)$result->num_rows
Next rowmysqli_fetch_assoc($result)$result->fetch_assoc()
Last new IDmysqli_insert_id($conn)$conn->insert_id
Closemysqli_close($conn)$conn->close()

1. Connect to MySQL

<?php
$servername = "localhost";
$username = "root";
$password = "";

// Create connection
$conn = mysqli_connect($servername, $username, $password);

// Check connection
if (!$conn) {
    die("Connection failed: " . mysqli_connect_error());
}
echo "Connected successfully";
?>

Output:

Connected successfully

  • On XAMPP the user is root with an empty password "". Handouts often show "username" / "password" as placeholders; those fail with Access denied.

  • die() prints the message and stops the script.

PHP 8.1+ behavior: MySQLi now throws an error instead of returning false. With a wrong password the page shows Fatal error: Uncaught mysqli_sql_exception: Access denied for user 'root'@'localhost' (using password: YES), and the if (!$conn) line is never reached. To get the handout's friendly "Connection failed: ..." message, put mysqli_report(MYSQLI_REPORT_OFF); at the top. Both were tested.

2. Create a database

<?php
$servername = "localhost";
$username = "root";
$password = "";

// Create connection
$conn = mysqli_connect($servername, $username, $password);
// Check connection
if (!$conn) {
    die("Connection failed: " . mysqli_connect_error());
}

// Create database
$sql = "CREATE DATABASE myDB";
if (mysqli_query($conn, $sql)) {
    echo "Database created successfully";
} else {
    echo "Error creating database: " . mysqli_error($conn);
}

mysqli_close($conn);
?>

Output (first run): Database created successfully

Second run: the database already exists. In PHP 8.1+ this is a fatal error (Can't create database 'myDB'; database exists), not the else message. Run the create scripts once.

  • mysqli_query($conn, $sql) sends the SQL. It returns true when it worked.

  • mysqli_error($conn) gives the database's error message.

Output:

New record created successfully. Last inserted ID is: 1

mysqli_insert_id($conn) returns the AUTO_INCREMENT id MySQL just gave the new row.

Insert several records:

$sql = "INSERT INTO MyGuests (firstname, lastname, email)
VALUES ('Mary', 'Moe', 'mary@example.com');";
$sql .= "INSERT INTO MyGuests (firstname, lastname, email)
VALUES ('Julie', 'Dooley', 'julie@example.com');";
$sql .= "INSERT INTO MyGuests (firstname, lastname, email)
VALUES ('Anna', 'Smith', 'anna@example.com')";

if (mysqli_multi_query($conn, $sql)) {
    echo "New records created successfully";
} else {

}

mysqli_close($conn);

Output: New records created successfully

  • .= adds text to the end of $sql, building one long string.

  • Each statement inside ends with ;. mysqli_multi_query() runs them all; plain mysqli_query() only runs one statement.

8. Prepared statements

Putting user input straight into SQL lets a user type SQL code into your form (SQL injection). A prepared statement sends the SQL with ? placeholders first, and the values separately, so the values are always treated as data.

// prepare and bind
$stmt = mysqli_prepare($conn, "INSERT INTO MyGuests (firstname, lastname, email) VALUES (?, ?, ?)");
mysqli_stmt_bind_param($stmt, "sss", $firstname, $lastname, $email);

// set parameters and execute
$firstname = "John";
$lastname = "Smith";
$email = "johnsmith@example.com";
mysqli_stmt_execute($stmt);

$firstname = "Ali";
$lastname = "Khan";
$email = "ali@example.com";
mysqli_stmt_execute($stmt);

echo "New records created successfully";

mysqli_stmt_close($stmt);
mysqli_close($conn);

Output: New records created successfully (John Smith gets id 5, Ali Khan id 6; id 3 is never reused).

Type letterMeans
iinteger
ddouble (decimal number)
sstring
bblob (binary data)

"sss" means three strings, one letter per ?, in order. The statement is prepared once and executed twice with different values.

The two ways to mix PHP and HTML:

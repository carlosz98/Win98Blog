Topic 1: Sessions

What is a session?

A session is a visitor's time browsing a website, from the first page they open until they stop using the site. In web development it means a way to keep information about one user across many requests.

  • The session data is stored on the server, for that one user, during their visit.

  • It is what makes personal, interactive pages possible: who is logged in, what is in the cart, the user's preferences.

Why do we need sessions?

HTTP (and HTTPS) is stateless: the server does not remember anything between one request and the next. Every request is independent, even if it comes from the same person on the same device one second later.

Sessions tie those requests together, so things like multi-page forms and shopping carts work.

  • Session variables hold information about one single user and are available to all pages of the application (for example the username or favorite color).

  • By default they last until the user closes the browser.

  • The variables and their values are stored on the server.

In simple words: HTTP forgets you after every page. A session is the server's notebook about you, and the session ID is the page number that tells it which notes are yours.

How does it work?

  1. The user connects to the website. The server establishes a session (some sites only create it when the user logs in).

  2. The server keeps the session data in a store (files, memory, or a database), generates a session ID, and sends it to the browser, usually as a cookie.

  3. Every following request from the browser includes the session ID, so the server knows which data belongs to this user.

  4. The server checks the session ID on each request. If it is valid, it carries out the request.

  5. The session is terminated and the ID stops being valid: the user logs out, closes the browser, or the session times out after a period of inactivity.

Step 3 can repeat many times (one per request), and step 4 is the response to each one.

Diagram from the class handout (TechTarget).

What is a session ID?

A session ID (or session token) is a unique identifier the web server gives to a user for the length of the current session.

  • The most common way to keep it is a cookie in the browser. That cookie is usually deleted when the session ends (or it can be set to expire at a specific date and time).

  • If cookies are disabled, the ID can be added to the URL instead. This is riskier: someone who sees the URL can hijack the session, and it can mess up how search engines index the pages.

  • Another option is a hidden form field, which also has limits.

In PHP the session cookie is named PHPSESSID. Testing demo_session1.php below, the server's response included this header:

Set-Cookie: PHPSESSID=3875f63234dde999e643935de41a5346; path=/

Only that random ID goes to the browser. The actual values (green, cat) stay on the server.

Topic 2: Sessions in PHP

The basic steps

1. Start a session: session_start() begins a new session (and creates a session ID), or resumes the existing one.

<?php
session_start();
?>

Note: session_start() must be the very first thing in the file, before any HTML tags. It sends the session cookie, which is a header, and headers must go before any output (the same rule as header() in Assignment 1).

2. Store session data: save key-value pairs in the $_SESSION superglobal array.

<?php
session_start();
$_SESSION["Rollnumber"] = "11";
$_SESSION["Name"] = "Ajay";
?>

3. Read session data: call session_start() first, then use the key.

<?php
session_start();
echo 'The Name of the student is :' . $_SESSION["Name"] . '<br>';
echo 'The Roll number of the student is :' . $_SESSION["Rollnumber"] . '<br>';
?>

Output (after the page above saved the values):

The Name of the student is :Ajay
The Roll number of the student is :11

4. Delete one session variable: unset() with that key.

<?php
session_start();
if (isset($_SESSION["Name"])) {
    unset($_SESSION["Rollnumber"]);
}
?>

This removes only Rollnumber. Name is still saved.

5. Destroy the whole session: session_destroy(), which takes no arguments.

<?php
session_start();
session_destroy();
?>
Function / variableWhat it does
session_start()Starts a new session or resumes the current one. Needed at the top of every page that uses sessions.
$_SESSION["key"] = value;Saves a value in the session.
$_SESSION["key"]Reads a saved value.
isset($_SESSION["key"])Checks that the value exists before using it.
unset($_SESSION["key"])Deletes one value.
session_unset()Deletes all the values, but the session itself stays.
session_destroy()Destroys the session data on the server.

Example: passing data between two pages

Page 1: demo_session1.php starts a session and sets two session variables.

<?php
// Start the session
session_start();
?>
<html>
<body>
<?php
// Set session variables
$_SESSION["favcolor"] = "green";
$_SESSION["favanimal"] = "cat";
echo "Session variables are set.";
?>
</body>
</html>

Output:

Session variables are set.

Page 2: demo_session2.php reads the values set on page 1.

<?php
session_start();
?>
<html>
<body>
<?php
// Echo session variables that were set on previous page
if (isset($_SESSION['favcolor'])) {
    echo "Favorite color is " . $_SESSION["favcolor"] . ".<br>";
    echo "Favorite animal is " . $_SESSION["favanimal"] . ".";
}
?>
</body>
</html>

Output (open page 1 first, then page 2 in the same browser):

Favorite color is green.
Favorite animal is cat.

  • The variables are not passed to page 2 in a link or a form. Page 2 gets them from the session it opens with session_start().

  • All session values live in the global $_SESSION array.

  • If page 2 is opened in a different browser (or before page 1), there is no session yet, so isset() is false and the page is blank. The isset() check is what prevents an "Undefined array key" warning.

Modify a session variable

To change a session variable, just overwrite it:

<?php
session_start();
?>
<html>
<body>
<?php
// to change a session variable, just overwrite it
$_SESSION["favcolor"] = "yellow";
echo "New Favorite color is " . $_SESSION["favcolor"] . ".<br>";
?>
</body>
</html>

Output:

New Favorite color is yellow.

Opening demo_session2.php afterwards prints Favorite color is yellow.

Destroy a session

To remove all the session variables and destroy the session, use session_unset() and session_destroy():

<?php
session_start();
?>
<html>
<body>
<?php
unset($_SESSION["favcolor"]);
// remove all session variables
session_unset();
// destroy the session
session_destroy();
?>
</body>
</html>

Output: a blank page (nothing is echoed). Opening demo_session2.php afterwards is also blank, because the values are gone.

  • unset($_SESSION["favcolor"]) removes one value. In this example it is not really needed, since session_unset() on the next line removes all of them.

  • session_unset() empties the $_SESSION array. session_destroy() deletes the session's data on the server. A logout page uses both.

Topic 3: Cookies

What is a cookie?

A cookie is a small text file the browser stores on the user's computer, at the request of a web server. Cookies remember user data (login details, preferences, activity) across multiple visits. Every time the browser sends a request to a site, it automatically includes the cookies for that domain.

"Across multiple visits" means the information is still there the next time the user comes back, even after closing the browser or shutting down the computer. Without cookies, everything (login, preferences, cart) would be lost when the browser closes.

ScenarioWhat the cookie does
Login: you check "Remember Me"Saves your username, so next time the site recognizes you and logs you in.
Language or theme: you pick Dark Mode or SpanishSaves the choice, so the site loads it automatically next time.
Shopping cart: you add items and leaveThe items are still there when you come back.

Cookies are commonly used to store preferences, keep users logged in, track activity across visits, and customize content for returning users.

Create a cookie: setcookie()

setcookie(name, value, expire, path, domain, secure, httponly);

Only name is required. All the other parameters are optional.

ParameterMeaning
nameThe cookie's name (the key in $_COOKIE).
valueWhat it stores.
expireWhen it expires, as a Unix timestamp: time() (now, in seconds) plus how many seconds it should live. If left out, the cookie is deleted when the browser closes.
pathWhich folders of the site can read it. "/" means the whole site.
domainWhich domain can read it.
securetrue = only sent over HTTPS.
httponlytrue = JavaScript cannot read it (helps against XSS).

Create and read a cookie

This creates a cookie named user with the value John Doe that expires in 30 days (86400 * 30 seconds; 86400 is one day). Then it reads it from $_COOKIE, using isset() to check that it exists.

<?php
$cookie_name = "user";
$cookie_value = "John Doe";
setcookie($cookie_name, $cookie_value, time() + (86400 * 30), "/"); // 86400 = 1 day
?>
<html>
<body>
<?php
if (!isset($_COOKIE[$cookie_name])) {
    echo "Cookie named '" . $cookie_name . "' is not set!";
} else {
    echo "Cookie '" . $cookie_name . "' is set!<br>";
    echo "Value is: " . $_COOKIE[$cookie_name];
}
?>
</body>
</html>

Output, first time you open the page:

Cookie named 'user' is not set!

Output, after you refresh:

Cookie 'user' is set!
Value is: John Doe

Why "not set" the first time? setcookie() only asks the browser to save the cookie (it goes out in the response). $_COOKIE holds the cookies the browser sent with this request, and on the first visit it had none. On the next request the browser sends it back, so it shows up. I tested this: the first response had Set-Cookie: user=John%20Doe; expires=...; Max-Age=2592000; path=/ and printed "not set", and the second request printed the value.

  • Note: setcookie() must come before the <html> tag (before any output), because a cookie is sent as a header.

  • Note: the value is automatically URL-encoded when sent (the space became %20 above) and decoded when received. setrawcookie() skips the encoding.

Modify a cookie

Set it again with setcookie(). Here the value changes to Alex Porter:

<?php
$cookie_name = "user";
$cookie_value = "Alex Porter";
setcookie($cookie_name, $cookie_value, time() + (86400 * 30), "/");
?>
<html>
<body>
<?php
if (!isset($_COOKIE[$cookie_name])) {
    echo "Cookie named '" . $cookie_name . "' is not set!";
} else {
    echo "Cookie '" . $cookie_name . "' is set!<br>";
    echo "Value is: " . $_COOKIE[$cookie_name];
}
?>
</body>
</html>

Output: for the same reason as above, the first load still shows the old value (Value is: John Doe). After a refresh:

Cookie 'user' is set!
Value is: Alex Porter

Delete a cookie

Use setcookie() with an expiration date in the past:

<?php
// set the expiration date to one hour ago
setcookie("user", "", time() - 3600);
?>
<html>
<body>
<?php
echo "Cookie 'user' is deleted.";
?>
</body>
</html>

Output:

Cookie 'user' is deleted.

  • An expired cookie is removed by the browser.

  • The cookie was created with path "/", so to be sure it is deleted, use the same path: setcookie("user", "", time() - 3600, "/");. The handout leaves the path out, which only works when the page is in the site's root folder.

Check if cookies are enabled

Try to create a test cookie, then count the $_COOKIE array:

<?php
setcookie("test_cookie", "test", time() + 3600, '/');
?>
<html>
<body>
<?php
if (count($_COOKIE) > 0) {
    echo "Cookies are enabled.";
} else {
    echo "Cookies are disabled.";
}
?>
</body>
</html>

Output (with cookies on):

Cookies are enabled.

  • count($_COOKIE) is how many cookies the browser sent. More than 0 means the browser is accepting cookies.

  • The same first-visit rule applies: on the very first load in a brand-new browser with no cookies for the site, it can say "disabled" until you refresh.

Using a cookie to pass information between pages

Page 1: demo_cookie1.php

<?php
$name="userid";
$value="11";
$exp=time()+(60*60*24*30); // another way to make cookie expire after 30 days
setcookie($name,$value,$exp);
if (isset($_COOKIE['userid'])) {
    echo $_COOKIE['userid'] ;
}
?>

Output: blank on the first load, then 11 after a refresh.

60*60*24*30 is seconds × minutes × hours × days = 2,592,000 seconds, the same as 86400 * 30.

Page 2: demo_cookie2.php reads the cookie set on page 1.

<html>
<head>
</head>
<body>
<h1>Cookie values</h1>
<?php
if (isset($_COOKIE['userid'])) {
    echo $_COOKIE['userid'] ;
}
?>
</body>
</html>

Output (after visiting page 1):

Cookie values
11

Page 2 does not set anything; it just reads what the browser sends. Since demo_cookie1.php sets no path, the cookie only works for pages in the same folder, which is the case here.

Topic 4: Cookies vs. Sessions

Both store user information. They differ in where and how it is stored.

FeatureCookiesSessions
DefinitionSmall files stored on the user's computer by the browserServer-side storage that temporarily saves user data for a visit
PurposeRemember user data across visitsKeep user data while they browse many pages during one visit
Storage locationOn the client's computer, in a text fileOn the server; only the session ID is stored on the client, as a cookie
SecurityLess secure: users can view or change cookie dataMore secure: the data is on the server, not directly reachable by users
Best practiceDo not store sensitive data (like passwords)Good for sensitive or temporary data (like login status)
DurationDays, months, or years, depending on the expirationWhile the browser is open, or until the session times out
PersistencePersistent: can survive closing the browser (if an expiration is set)Temporary: destroyed on logout or when the browser closes
PHPsetcookie() and $_COOKIEsession_start() and $_SESSION
Use caseRecommended
Remember user preferences or site themeCookie
Keep a user logged in temporarilySession
Store secure or private dataSession
Track users between visitsCookie

Conclusion

  • Cookies = client-side storage → long-term and less secure.

  • Sessions = server-side storage → temporary and more secure.

  • In practice both are used together: the session ID is stored in a cookie so the server can find the user's session.

Passing values in the URL

Values can go in the URL itself. They are visible to the user and others (address bar and browser history), so this is not a safe way to send sensitive data like passwords.

main.php

<html>
<head>
</head>
<body>
<h1>Welcome to main page</h1>
<?php
$urltext="Contact Us";
?>
<a href="welcome.php?id=110&name=John&age=27"> <?php echo $urltext;?> </a>
</body>
</html>

Output: the heading Welcome to main page and a link that says Contact Us.

Clicking the link opens welcome.php and sends the data in the URL.

welcome.php

<html>
<head>
</head>
<body>
<h1>Welcome to contact page</h1>
<?php
//echo print_r($_GET);
?>
</br>
ID:<?php echo $_GET['id']; ?>
</br>
name:<?php echo $_GET['name']; ?>
</br>
age:<?php echo $_GET['age']; ?>
</body>
</html>

Output (after clicking Contact Us; the address bar shows welcome.php?id=110&name=John&age=27):

Welcome to contact page

ID:110
name:John
age:27
PieceMeaning
?Starts the query string.
id=110One key=value pair.
&Separates the pairs.
$_GET['id']Reads the value of id from the URL.
//echo print_r($_GET);Commented out. Removing the // prints the whole $_GET array, useful for debugging.

  • <?php echo $urltext;?> puts the PHP variable's text inside the link.

  • If welcome.php is opened without the ?id=... part, $_GET['id'] does not exist and PHP shows "Undefined array key" warnings. Use $_GET['id'] ?? '' or isset() to avoid them.

  • Anyone can edit the URL by hand (?name=<script>...), so printing $_GET values should use htmlspecialchars().

End of Week 5, Day 2 — Summary

Covered today

  • Why: HTTP is stateless, so sessions and cookies are how a site remembers a user between pages.

  • Sessions: data on the server, found through a session ID (PHPSESSID cookie). session_start() at the top of every page, $_SESSION to save and read, unset(), session_unset(), session_destroy().

  • Cookies: data in the browser. setcookie(name, value, expire, path, ...) to create, modify, or delete (past expiration), $_COOKIE to read, count($_COOKIE) to check they are enabled.

  • Cookies vs sessions: cookies are long-term and less secure; sessions are temporary and more secure; they work together.

  • Passing data between pages: sessions, cookies, POST/GET forms, and the URL query string (?id=110&name=John) read with $_GET.

Mistakes and traps to remember

  • session_start() and setcookie() must come before any HTML or echo, because they send headers.

  • A new cookie is not in $_COOKIE until the next request, so the first load says "not set".

  • Forgetting session_start() on a page means $_SESSION is empty there.

  • Never store passwords or private data in a cookie. Never send them in the URL.

  • Delete a cookie with the same path it was created with.

  • Check isset() before reading $_SESSION, $_COOKIE, or $_GET values.

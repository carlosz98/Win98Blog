Introduction to PHP — How is PHP Executed?

Big idea: PHP doesn't have to run through a web server. Besides sending HTML to a browser (what we did with Apache/XAMPP in class), PHP can also be run from the terminal as a general-purpose programming language — no HTML or web involved. When run this way, the program's output is printed straight to the terminal. That's handy for testing functionality or writing simple local programs.

Two ways PHP gets executed:

Web (what we did in class)Terminal (this lesson)
Started byBrowser requesting a .php page from ApacheRunning the file yourself from the command line
Output goes toThe browser, as HTMLThe terminal, as plain text
Needs a web server?Yes (Apache via XAMPP)No

Opening tag required, closing tag optional:

Every PHP file still has to start with <?php so PHP knows where the code begins. When a file contains only PHP, the closing ?> tag isn't needed — by convention it's left out.

<?php
echo "Hello, World!";

Running this prints Hello, World! to the terminal.

Whitespace is ignored:

PHP generally ignores tabs, spaces, and new lines, so extra spacing doesn't change the result. This produces exactly the same output as the example above:

<?php
echo     "Hello, World!";

PHP isn't always case-sensitive:

Keywords like echo work no matter how they're capitalized, so this runs too:

<?php
Echo "Hello, World!";

Even so, best practice is to stick with the standard casing — echo, not Echo.

📝 Extra detail worth remembering: the case-insensitivity applies to keywords and function names (echo, if, date()). Variable names are still case-sensitive — $name and $Name are two different variables.

Checkpoint exercise — print I love PHP! instead of Hello, World!:

<?php
echo "I love PHP!";

Only the text inside the quotes changes; the opening tag and echo stay the same.

Key takeaways:

  • PHP can run in the terminal, not just through a browser.

  • <?php is always required; the closing ?> is optional (and usually omitted) in PHP-only files.

  • Whitespace is ignored.

  • Keywords like echo aren't case-sensitive, but use standard casing anyway.

Introduction to PHP — PHP Comments

What comments are for: text placed in a file that the computer doesn't execute and the end user never sees. They're used to:

  • Annotate code so it's clearer to yourself or other developers.

  • Temporarily disable code — comment a line out to stop it running without deleting it (same idea as when we commented out the Subtotal line in the order form).

PHP has two main styles.

1. Single-line comments — // or #

Used for short explanations or quick clarifications. Anything after the symbol on that same line is ignored by PHP. Either symbol works:

// I will always remember this
echo "Hello world"; // My first PHP statement
# I will always remember this
echo "Hello, World!"; # My first PHP statement

A single-line comment can sit on its own line or at the end of a line of code.

2. Multi-line comments — /* ... */

Used for longer descriptions, a detailed guide to a section of code, or to disable several lines at once. Starts with /* and ends with */, and can span as many lines as needed:

/* This comment
   runs across
   several lines. */
echo "Hello, World!";

Quick comparison:

StyleSymbol(s)Best for
Single-line// or #Short notes, end-of-line explanations
Multi-line/* ... */Longer descriptions, disabling several lines

📝 Connects to class: in Week 2, Day 1 we used // and /* */. The # style is new here — it does exactly the same job as //. Most PHP code uses //, so that's the one to default to.

⚠️ Gotcha: a single-line comment stops at the end of the line or at a closing ?> tag, whichever comes first. So a ?> written inside a // comment will actually end PHP mode.

Checkpoint exercise: predict what shows up in the terminal and what doesn't, then run the code to check. The rule to apply: comments (single-line and multi-line) never appear in the output — only the echo statements do.

<?php
// This never shows up
echo "I am printed"; // neither does this part

/* echo "I am NOT printed"; */

(Illustrative example of the same idea — the second echo is commented out, so only "I am printed" reaches the terminal.)

Key takeaways:

  • Comments are ignored by PHP and never displayed.

  • // and # make single-line comments; /* ... */ makes multi-line ones.

  • Comments are also a quick way to switch code off without deleting it.

Introduction to PHP — Todo: Learn PHP

What this lesson is: a look at a working PHP application before diving into the details. It's a todo list, and the goal isn't to understand the code yet — it's to see how PHP behaves in a real app.

How it works behind the scenes: PHP runs on the back-end to build a dynamic website. Each time the visitor changes the task list, the browser makes a new request for the page, the PHP code runs again on the server, and it sends back a fresh version of the HTML with the updated list. That's the same request/response flow from Week 1: Browser → Apache → PHP → result → Browser.

Why a todo list? It's a classic demo for any web framework or technology because it shows all four CRUD behaviors in a small, familiar app:

Introduction to PHP — Review Questions

Q: When embedding PHP in HTML, what tags must be used to contain the PHP portion of code?

✅ <?php and ?>

When used inside HTML, both an opening and closing tag must be used for PHP — this is different from a PHP-only file, where the closing ?> can be left out (see How is PHP Executed? above). The distinction matters: once HTML is mixed in, PHP needs to know exactly where its code block ends so it can switch back to outputting plain HTML.

Q: Which is true about dynamic web pages?

✅ A dynamic PHP web page can provide a page that is customized for each visitor.

PHP generates HTML every time it's executed — not once and reused — so each request can produce a different result depending on things like form input, a logged-in user, or data pulled from a database. That's the whole reason the todo app updates immediately after adding/completing/deleting a task: every action is a fresh request, and PHP builds a brand-new page in response.

This connects directly to the order form from Week 2: the same processorder.php file produces a completely different result depending on what quantities were submitted — that's a dynamic page in action.

PHP Strings and Variables — Creating Variables

Two things happen in one statement:

$my_name = "Aisle Nevertell";

This line does two jobs at once:

  1. Declares a new variable named my_name.

  2. Assigns it the value "Aisle Nevertell".

After this runs, $my_name holds that string. These two steps can be done separately, but in practice they're almost always combined into one line like this.

The pieces:

  • $ — the sigil, a character that marks something as a variable so the computer (and other developers) can spot it instantly. Every PHP variable starts with one.

  • = — the assignment operator, covered earlier (Week 2) as different from ==. Here it's doing exactly that job: assigning the value on the right to the variable on the left.

Naming rules for variables:

  • Can contain letters, numbers, and underscores (_).

  • Must start with a letter or underscore — never a number.

  • Case-sensitive — $my_example and $My_example are two completely different variables. (This is the same case-sensitivity idea from the How is PHP Executed? lesson — except there it was about keywords like echo NOT being case-sensitive. Variables are the opposite: they ARE case-sensitive.)

Naming convention — snake_case:

When a variable name has more than one word, PHP convention is to separate the words with underscores — known as snake_case:

$mood = ":)";
$favorite_food = "Red curry with eggplant";

📝 Connects to class: this is exactly the naming style already used in the order form — $tireqty, $oilqty, $totalamount all follow this same lowercase, no-space pattern (though not always with underscores between words).

Checkpoint exercises:

<?php
// 1. Any variable holding a string
$myName = "Carlos Vargas";

// 2. $biography — starts with a newline character, then a sentence about yourself
$biography = "\nMy Bio";

// 3. $favorite_food — concatenating "\n", "tur", "duck", and "en" together
$favorite_food = "\n" . "tur" . "duck" . "en";
// $favorite_food now holds: "\nturducken"

  • "\n" — the newline escape sequence inside a double-quoted string; it inserts a line break into the string's value (won't visually show a break in HTML output without <br>, but it does in plain terminal output).

  • Checkpoint 3 is a concatenation exercise using . — the same operator from Week 2 — chaining four separate strings ("\n", "tur", "duck", "en") into one: "\nturducken".

Key takeaways:

  • A variable is declared and assigned together with $name = value;.

  • Variable names: letters/numbers/underscores, must start with a letter or underscore, and are case-sensitive.

  • snake_case (underscores between words) is the PHP convention for multi-word variable names.

  • "\n" is a newline character usable inside double-quoted strings.

PHP Strings and Variables — Using Variables

Once declared, a variable can be reused as many times as needed — just reference it with $ + its name, and it'll be replaced by the value it holds:

$favorite_food = "Red curry with eggplant, green beans, and peanuts";
echo $favorite_food;
// Prints: Red curry with eggplant, green beans, and peanuts
$dog_name = "Tadpole";
echo $dog_name;
// Prints: Tadpole

The rule: except during assignment (the moment $var = value runs), anywhere else the computer sees a variable, it swaps in the value the variable holds. Because of this, a variable can be used in an operation exactly like a plain value of that type would be — including concatenation:

$dog_name = "Tadpole";
echo "My dog is named " . $dog_name;
// Prints: My dog is named Tadpole

Combining several variables in one line:

$dog_name = "Tadpole";
$favorite_food = "salmon";
$color = "brown";

echo "I have a " . $color . " dog named " . $dog_name . " and her favorite food is " . $favorite_food . ".";
// Prints: I have a brown dog named Tadpole and her favorite food is salmon.

Each . glues one more piece — literal text or a variable's value — onto the growing string, same as we did building up the order form's output ("Total including tax: " . number_format($totalamount, 2) . "<br>").

Checkpoint exercise — create $name and $language:

<?php
$name = "Carlos";
$language = "PHP";

Key takeaways:

  • A variable is referenced the same way it's declared: $ + name.

  • Outside of assignment, PHP always substitutes a variable's current value wherever it's used.

  • Variables can be concatenated with . right alongside literal strings, and several variables can be chained together in one echo statement.

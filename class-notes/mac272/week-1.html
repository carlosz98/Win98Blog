What is a PHP file?

A PHP file is a text file (extension .php) that mixes HTML and PHP code. When a browser requests it, the server executes any PHP code inside, then sends only the resulting HTML to the browser — the client never sees the PHP source itself.

<!DOCTYPE html>
<html>
<body>

<?php
  echo "Hello, world!";
?>

</body>
</html>

Getting Started

Tools needed:

  • A code editor (e.g. VS Code, PHPStorm)

  • PHP installed (interpreter to run .php files)

  • A web server (Apache, Nginx, or similar) to handle requests

  • MySQL installed for the database

  • A browser to view the result

Professor recommends: Brackets (code editor) + XAMPP (local server stack). Using VS Code instead of Brackets here.

Web servers — Apache vs. others:

  • Apache — the most common web server for PHP; handles .php files out of the box via mod_php, widely supported, huge community, easy to configure with .htaccess files.

  • Nginx — a faster, more lightweight alternative; doesn't run PHP directly — it hands .php requests off to a separate process (PHP-FPM) to execute, then returns the result. Popular for high-traffic sites needing better performance under load.

How the server processes an incoming request:

Simple flow: Browser → Apache → PHP → result → Browser

Apache receives the request and, seeing the .php extension, hands the file to PHP instead of serving it as plain text. PHP runs the code (logic, DB queries, etc.) and generates HTML. That HTML goes back through Apache to the browser — the visitor only ever sees the output, never the PHP source.

Example with a database:

Browser → Apache → PHP → MySQL → PHP → Apache → Browser

The browser requests a page → Apache hands it to PHP → PHP queries MySQL for data (e.g. SELECT * FROM users) → MySQL returns the result to PHP → PHP builds that data into HTML → the HTML goes back through Apache → the browser displays the final page.

  1. The browser sends an HTTP request for a page (e.g. index.php) to the web server.

  2. The web server sees the .php extension and passes the file to the PHP interpreter (directly, or via PHP-FPM for Nginx).

  3. PHP executes the code — running logic, querying MySQL if needed, and building the page content.

  4. PHP hands the generated HTML back to the web server.

  5. The web server sends that HTML back to the browser as the HTTP response — the visitor only ever sees HTML, never the PHP code.

XAMPP:

XAMPP is a free, cross-platform local development stack that bundles everything needed to run PHP + MySQL projects on your own computer: X (cross-platform) + Apache + MySQL/MariaDB + PHP + Perl. Instead of installing and configuring each tool separately, XAMPP installs them together with a simple control panel to start/stop Apache and MySQL — making it the easiest way to get a local PHP + MySQL environment running for practice and development before deploying to a real server.

XAMPP includes:

  • Apache — the web server

  • MySQL/MariaDB — the database

  • PHP — the scripting language/interpreter

  • phpMyAdmin — a web-based GUI for managing MySQL databases

  • Perl — another scripting language (optional)

How the stack works in practice:

  1. Client request — the browser requests a page from the server.

  2. Web server processes the request — Apache receives it and routes .php files to PHP.

  3. PHP executes the script — runs the code, talks to MySQL/MariaDB if needed, builds the output.

  4. Response is sent — the generated HTML goes back through Apache to the browser.

PHP parser: the part of the PHP engine that reads a .php file, checks its syntax, and converts the code into a form the interpreter can execute step by step — it's what catches syntax errors before the script actually runs.

Key Features of XAMPP:

  • All-in-one package — bundles Apache, MySQL/MariaDB, PHP, and Perl together, so there's nothing extra to install separately.

  • Cross-platform — available for Windows, macOS, and Linux.

  • User-friendly interface — a simple control panel to start/stop Apache and MySQL with one click, plus phpMyAdmin for managing databases visually.

  • Open source — free to download and use.

Key Features of PHP

  • Server-side execution — PHP code runs on the server before the page is sent to the browser; the client only ever sees the resulting HTML.

  • Ease of use — simple, C-like syntax that's beginner-friendly and quick to write.

  • Open source — free to use, with a large community and extensive documentation.

  • Cross-platform — runs on Windows, Linux, macOS, and most web servers (Apache, Nginx, etc.).

  • Integration with databases — strong native support for MySQL and other databases, making it easy to build data-driven sites.

  • Built-in functions — a huge standard library (string handling, arrays, file I/O, etc.) with no extra setup needed.

  • Interoperability — works well with HTML, JavaScript, XML, and other web technologies, and can talk to many external services/APIs.

  • Security features — includes tools for input validation, encryption (e.g. password_hash()), and session management to help build secure applications.

Hashing vs. encryption: hashing (e.g. password_hash()) is one-way — you can't get the original value back, it's used to verify data like passwords. Encryption is two-way — data is scrambled with a key and can be decrypted back to its original form, used when you need to recover the original data later.

Why/when to use each:

  • Hashing — for storing passwords (password_hash() / password_verify()) and checking data integrity (e.g. verifying a downloaded file wasn't corrupted). Useful because you never need the original value back — you only ever need to check if an input matches. Even if the database is breached, attackers only get hashes, not real passwords.

  • Encryption — for data you'll need to read again later, like a credit card number, address, or private messages, and for protecting sensitive data in transit or at rest. Useful because it's reversible with the right key, so the app can decrypt and use the real value when needed.

Rule of thumb: if you'll ever need the original value back, encrypt it. If you only ever need to check whether an input matches, hash it. Using encryption for passwords is risky (a leaked key exposes every password); using hashing for something like a credit card number would make the data useless to your own app.

Introduction to MySQL

MySQL is an open-source relational database management system (RDBMS) used to store, organize, and retrieve data — commonly paired with PHP to power the data layer of web applications.

Key Features of MySQL

  • Relational database structure — data is organized into tables with rows and columns, and tables can be linked to each other through relationships (e.g. foreign keys).

  • SQL language — uses Structured Query Language (SQL) to create, read, update, and delete data (CRUD), as well as manage the database structure itself.

  • Open source — free to use, widely supported, with a large community and strong documentation.

  • Cross-platform — runs on Windows, Linux, macOS, and integrates with most web server environments.

  • High performance — optimized for fast read/write operations, even with large datasets.

  • Scalability — can handle anything from small personal projects to large, high-traffic applications.

  • Integration — connects easily with many languages and platforms, especially PHP (via mysqli or PDO), making it a natural pairing for web apps.

  • Dynamic content management — MySQL stores content (posts, products, user records) that can be created, updated, or removed without changing the site's code, powering things like blogs, e-commerce catalogs, and admin dashboards.

Example:

INSERT INTO posts (title, content, created_at) VALUES ('New Post', 'Post content here', NOW());

(Adding a row to a posts table — the site's content updates dynamically without touching the PHP code.)

PHP + MySQL

PHP connects to MySQL to read and write data behind a website — this is the core of most dynamic web apps (login systems, forms, dashboards, etc.).

  • mysqli — the MySQL-specific extension for PHP; simpler, works only with MySQL.

  • PDO (PHP Data Objects) — a more flexible extension that works with MySQL and other databases (Postgres, SQLite, etc.) using the same syntax.

<?php
$conn = new mysqli("localhost", "username", "password", "database_name");

if ($conn->connect_error) {
    die("Connection failed: " . $conn->connect_error);
}

$result = $conn->query("SELECT * FROM users");
while ($row = $result->fetch_assoc()) {
    echo $row["username"];
}

$conn->close();
?>

(Basic example — connects to a database, runs a query, and loops through the results.)

SQL injection: malicious SQL slipped in through user input; avoid it by using prepared statements instead of raw string queries.

Benefits of PHP + MySQL Together

  • Ease of integration — PHP has built-in extensions (mysqli, PDO) made specifically to talk to MySQL, so connecting the two takes very little setup.

  • Cost effectiveness — both are open source and free, keeping hosting and development costs low.

  • Scalability — the combination handles everything from small personal sites to large, high-traffic applications.

  • Security — both provide built-in tools (prepared statements, hashing functions, etc.) to help build secure applications.

Career Notes

ServiceNow & JavaScript

ServiceNow is a major enterprise IT platform (ticketing, workflow automation, ITSM) worth knowing about as a JS developer:

  • Server-side scripting (Business Rules, Script Includes) runs on Rhino/GlideScript — a JavaScript-based engine, so core JS skills (functions, objects, async patterns) carry over directly.

  • Client-side scripting (Client Scripts, UI Policies) is vanilla JS against ServiceNow's form DOM (g_form, g_user APIs) — same JS, a proprietary API layer on top.

  • Newer app development (Service Portal, UI Builder) leans on AngularJS/modern JS, so front-end skills transfer even more directly.

  • Career angle: ServiceNow dev/admin roles are in high demand and pay well; the ramp-up from a JS background is shorter than learning it cold, making it a solid pivot or side-skill.

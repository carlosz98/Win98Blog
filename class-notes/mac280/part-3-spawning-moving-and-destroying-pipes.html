Part 3: Spawning, moving and destroying pipes

Part 3 makes an endless level: pipes slide left, a spawner creates new ones on a timer at random heights, and old ones are deleted once off screen.

Moving the pipes

This script goes on the pipe (call it something like PipeMoveScript).

public float moveSpeed = 5;
public float deadZone = -45;

void Update()
{
    transform.position = transform.position + (Vector3.left * moveSpeed) * Time.deltaTime;

    if (transform.position.x < deadZone)
    {
        Destroy(gameObject);
    }
}

  • transform.position is the object's current position. Vector3.left is (-1, 0, 0).

  • Time.deltaTime is the time since the last frame. Multiplying by it makes movement frame-rate independent, so the pipe moves at the same real speed on a fast or slow computer.

  • deadZone: once a pipe passes x = -45 it is destroyed. This prevents a pile-up of unused objects, keeps performance smooth and keeps the scene clean.

Prefabs

  1. Select the parent pipe GameObject in the Hierarchy.

  2. Drag it into the Project panel. This creates a prefab, a blueprint that stores the object, its children, components and settings.

  3. Delete the original from the Hierarchy; the prefab lives in the Project panel.

Editing the prefab updates every copy, which keeps things consistent as the game grows.

The Pipe Spawner

  1. Create a new GameObject named Pipe Spawner and place it just right of the camera.

  2. Create a script (PipeSpawnScript) and attach it.

  3. Drag the pipe prefab from the Project panel into the script's pipe slot in the Inspector.

public GameObject pipe;
public float spawnRate = 2;
private float timer = 0;
public float heightOffset = 10;

void Start()
{
    spawnPipe(); // first pipe right away
}

void Update()
{
    if (timer < spawnRate)
    {
        timer = timer + Time.deltaTime;
    }
    else
    {
        spawnPipe();
        timer = 0;
    }
}

void spawnPipe()
{
    float lowestPoint = transform.position.y - heightOffset;
    float highestPoint = transform.position.y + heightOffset;
    Instantiate(pipe, new Vector3(transform.position.x, Random.Range(lowestPoint, highestPoint), 0), transform.rotation);
}

  • spawnRate is seconds between pipes. timer is private, so it does not appear in the Inspector.

  • Instantiate(prefab, position, rotation) creates a copy of the prefab. The slides' alternative version uses Quaternion.identity (no rotation) instead of transform.rotation.

  • Random.Range(low, high) picks a random float between the two values, so each pipe gets a different Y while X stays at the spawner. Z is 0 because the game is 2D.

Two versions of the spawner

The slides compare putting Instantiate directly inside Update() with moving it into its own spawnPipe() function. The separate function is the better choice: it is modular (callable from Start() too), readable (Update() only handles the timer) and maintainable (change spawning in one place). The inline version is simpler and fine for tiny projects.

Heads up: one slide says the first script has the commented-out spawn call in Start(), but in the code shown it is the alternative (second) script that has it. Also, C# is case-sensitive, so SpawnPipe() and spawnPipe() are different names; pick one and use it everywhere.

Likely test points

  • Why multiply by Time.deltaTime (frame-rate independent movement and timing).

  • What a prefab is and how to make one (drag from Hierarchy to Project).

  • The three arguments of Instantiate: object, position, rotation.

  • How the timer works: add deltaTime until it reaches spawnRate, spawn, reset to 0.

  • How the random height range is computed (spawner Y minus and plus heightOffset).

  • Why destroy off-screen objects (memory and performance).

  • Why a separate function is better design (modularity, readability, maintainability).

Lecture 9: Exception Handling

Exception handling uses try, throw and catch so a program can deal with runtime errors and keep running or fail gracefully instead of crashing.

  • try: wraps code that might fail.

  • throw: signals an error (any type: int, string, or an exception object).

  • catch: handles it. try and catch come in pairs.

  • Why: prevents crashes, handles errors at runtime, keeps error code separate from normal logic.

Standard exceptions (#include <stdexcept>, all derived from std::exception)

ExceptionThrown when
std::runtime_errorAn error happens during execution (invalid operation, unexpected condition)
std::out_of_rangeAccessing past the end of a container, e.g. vector::at()
std::invalid_argumentA function gets an argument that isn't valid
std::bad_allocnew can't get enough memory (e.g. new int[1000000000], about 4 GB)

A vector is a dynamic array: it resizes itself as you add or remove elements and manages its own memory, unlike a raw array.

#include <iostream>
#include <stdexcept>
#include <vector>
using namespace std;

class MyException : public exception {          // user-defined exception
    string errorMessage;
public:
    MyException(string msg) : errorMessage(msg) {}
    const char* what() const noexcept override {  // override what()
        return errorMessage.c_str();
    }
};

void checkValue(int v) {
    if (v < 0) throw MyException("Negative value not allowed");
}

int divide(int a, int b) {
    if (b == 0) throw runtime_error("Division by zero!");
    return a / b;
}

int main() {
    try {
        vector<int> v = {1, 2, 3};
        checkValue(-5);
        cout << v.at(10);          // would throw out_of_range
        divide(10, 0);
    }
    catch (const MyException& e)  { cout << "Custom: " << e.what() << "\n"; }
    catch (const out_of_range& e) { cout << "Range: " << e.what() << "\n"; }
    catch (const exception& e)    { cout << "Other: " << e.what() << "\n"; }
    catch (...)                   { cout << "Unknown error\n"; }
    return 0;
}
// Output: Custom: Negative value not allowed

The first throw jumps straight to the matching catch; the remaining lines in try never run.

Making a user-defined exception (3 steps): inherit from std::exception, override what() to return the message, throw an instance when the error happens. Why: specificity, readability, flexibility (extra data like error codes), reusability.

Common mistakes

  • Putting catch (const exception& e) before more specific catches. It matches everything derived from it, so the specific ones never run. Order catches from most specific to most general.

  • Catching by value instead of const& (copies and can slice the exception).

  • Using v[10] and expecting an exception; only v.at(10) checks bounds and throws.

  • Forgetting delete[] after a successful new[].

Likely test points: the three keywords, the four standard exceptions and when each is thrown, the three steps for a custom exception, ordering multiple catch blocks, predicting output after a throw.

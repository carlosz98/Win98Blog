Chapter 11: Compression, System Backup and Software Installation

Shrink files with compress, gzip or bzip2; back them up with tar, cpio or dump; and install software from source (make) or with a package manager (rpm/dnf on Red Hat, dpkg/apt-get on Debian).

Compression utilities

UtilityAlgorithmAvg ratioExtensionViewDecompress
compressLZW (Adaptive Lempel-Ziv)40-50%.Zzcat, zmore, zlessuncompress
gzipLZ77 (Lempel-Ziv)60-70%.gzzcat, zmoregunzip
bzip2Burrows-Wheeler + Huffman50-75%.bz2bzcatbunzip2

  • Compression ratio = the percent the file shrank.

  • gzip's edge: you pick the level, -1 (fastest) to -9 (best).

  • bzip2 can't compress a whole directory and needs bzcat, not zcat.

Backups

  • Archive = a file or device holding copies of files. Keep archives at another location.

  • Back up home directories and important config files (and service data).

  • tar is the most common. It does not compress by itself; add -z (gzip), -j (bzip2) or -Z (compress). A compressed tar = tarball.

  • cpio also backs up device files and long names; uses absolute paths by default.

  • dump / restore back up whole ext2/3/4 filesystems. Level 0 = full, 1-9 = incremental (changes since the last lower level). History is in /etc/dumpdates.

  • Full backup = everything. Incremental = only what changed since the last backup.

  • For CD/DVD use burning software (e.g. GnomeBaker), not tar.

Software installation

  • Software comes as precompiled binaries or source code you compile.

  • From source: ./configure, then make (reads the Makefile and compiles), then make install (copies programs into place). Source is usually a tarball.

  • Package manager = installs, queries and removes packages in a standard format.

  • RPM (Red Hat, Fedora): files end in .rpm, name shows the architecture. A dependency error means another package must be installed first.

  • dnf (newer yum) pulls packages from repositories and installs dependencies for you. Package group = related packages installed together.

  • DPM (Debian, Ubuntu): files end in .deb, managed by dpkg, database in /var/lib/dpkg. apt-get downloads from repositories; aptitude works like apt-get.

Commands

gzip -v -9 file         # compress, best level (makes file.gz)
gunzip file.gz          # decompress
zcat file.gz            # view without decompressing
bzip2 file ; bzcat file.bz2 ; bunzip2 file.bz2
compress -v file ; uncompress file.Z
tar -cvf home.tar /home         # create archive
tar -czvf home.tar.gz /home     # create gzip tarball
tar -tvf home.tar               # list contents
tar -xvf home.tar               # extract
tar -rvf /dev/st0 newfile       # append to archive on tape
find /etc | cpio -ocvB > /root/etc.cpio   # cpio backup
cpio -ivdB < /root/etc.cpio               # cpio restore
dump -0uf /dev/st0 /home        # full (level 0) backup
restore -rf /dev/st0            # restore it
rpm -ivh pkg.rpm        # install
rpm -q bash             # is it installed? full name
rpm -qi bash            # package info
rpm -qf /bin/ls         # which package owns this file
rpm -e pkg              # remove
dnf install bluefish ; dnf update bluefish ; dnf search editor
dnf grouplist           # list package groups
dpkg -i pkg.deb ; dpkg -l      # install .deb / list installed
apt-get install pkg ; apt-get remove pkg ; apt-get purge pkg
apt-get update ; apt-get upgrade
apt-cache search editor

Likely test points

  • Match each compression tool to its extension, ratio and view/decompress command.

  • tar -c -t -x -v -f -z -j and that tar alone doesn't compress.

  • dump level 0 vs 1-9; full vs incremental; /etc/dumpdates.

  • make vs make install; what the Makefile is.

  • rpm -i -q -qi -qf -e; dnf installs dependencies, rpm doesn't.

  • .rpm vs .deb; dpkg vs apt-get; update vs upgrade.

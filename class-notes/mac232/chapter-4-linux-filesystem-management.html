Chapter 4: Linux Filesystem Management

This is the heaviest test chapter: managing files, finding them, links, ownership and permissions (regular, numeric, umask, special, ACLs, attributes).

Key concepts

  • FHS (Filesystem Hierarchy Standard): the standard set of directories (/etc, /bin, /home, /var...) so software and admins can find files on any distro.

  • cp and mv ask before overwriting in Fedora because BASH has aliases (cp -i, mv -i). -f forces. rmdir only removes empty directories.

  • Finding files: locate searches a prebuilt database (fast, refresh with updatedb); find searches the live tree (slower, more options); which searches the PATH variable (also type, whereis).

  • Filesystem structure: superblock (info about the filesystem: inode count, block size), inode table (one inode per file: size, block locations, modified date, permissions, owner), data blocks (the content).

  • Hard link: two names, same inode, must be on the same filesystem. Deleting one just lowers the link count.

  • Symbolic link: its own inode; it only stores the path to the target. Can cross filesystems. Breaks if the target is deleted.

  • Ownership: the creator's user and primary group own a new file. chown / chgrp, -R for recursive.

  • Mode = permissions stored in the inode, in three sets: user (owner), group, other. Permissions are not additive: Linux uses the first set that matches, in the order user, group, other.

  • Directory permissions: r = list contents, w = add/remove files, x = enter the directory (r and w need x to be useful).

Numeric permissions

PermissionValue
r (read)4
w (write)2
x (execute)1

Add them per set: rwxr-x--- = 7 5 0 = 750. rw-r--r-- = 644. rwxrwxrwx = 777.

umask (default permissions)

New files start at 666 (rw-rw-rw-) and new directories at 777. The umask is subtracted from those.

umaskNew fileNew directory
022644 rw-r--r--755 rwxr-xr-x
002664 rw-rw-r--775 rwxrwxr-x
007660 rw-rw----770 rwxrwx---

Special permissions

PermissionNumberShows asWhat it does
SUID4000s in user x spotRuns as the file's owner (e.g. passwd). Binaries only, not scripts; nothing on directories.
SGID2000s in group x spotFile: runs with the file's group. Directory: new files get the directory's group.
Sticky bit1000t in other x spotDirectories only: users can delete only their own files (e.g. /tmp).

A capital S or T means the special bit is set but execute is not.

Commands

mkdir projects            # make a directory
mv old.txt new.txt        # rename (or move)
cp -r dir1 dir2           # copy a directory recursively
rm -f file ; rm -r dir    # force remove ; remove directory tree
alias                     # list shell aliases
updatedb ; locate .bashrc # refresh database, then search it
locate -i '*.txt'         # case-insensitive
find /etc -name "*.conf"  # quote wildcards for find
find / -user carlos       # files owned by a user
find /var -size +1M       # files bigger than 1 MB
which ls                  # where is the ls program
ln file1 hardlink         # hard link
ln -s /etc/hosts mylink   # symbolic link
ls -li                    # show inode numbers
whoami ; groups           # who am I, my groups
touch empty.txt           # create empty file
chown carlos:staff file   # change owner and group
chgrp -R staff dir        # change group recursively
chmod u+x,g-w script.sh   # symbolic mode (u g o a, + - =, r w x)
chmod 755 script.sh       # numeric mode
chmod 4755 prog           # add SUID
chmod 1777 /shared        # add sticky bit
umask ; umask 007         # show / set umask
setfacl -m u:bob:r file   # give bob read in the ACL
setfacl -b file           # remove all extra ACL entries
getfacl file              # list ACL
chattr +i file ; lsattr file   # make immutable, list attributes

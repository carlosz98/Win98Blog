Strict Declaration — declare(strict_types=1)

Definition: by default, PHP is forgiving about types — if a function expects an int and receives the string "5", PHP quietly converts it (type juggling). A strict declaration turns that forgiveness off for function calls and return values in the file where it's declared: PHP now requires the exact type, and throws a TypeError if it doesn't get it.

<?php
declare(strict_types=1); // must be the very first statement in the file

function add(int $a, int $b): int {
    return $a + $b;
}

echo add(5, 10);    // 15 — both arguments really are ints
echo add("5", 10);  // ❌ Fatal error: Uncaught TypeError — "5" is a string, not an int
?>

The same code without the strict declaration (PHP's default "weak"/coercive mode):

<?php
function add(int $a, int $b): int {
    return $a + $b;
}

echo add("5", 10); // 15 — PHP silently converts the numeric string "5" to the int 5
?>
Weak mode (default)Strict mode (strict_types=1)
Passing "5" to an int parameterAccepted — converted to 5TypeError
Returning the wrong type from a functionConverted if possibleTypeError
Passing an int to a float parameterAcceptedStill accepted — the one allowed exception (an int can safely widen to a float)
Non-numeric string ("abc") to an int parameterTypeErrorTypeError

Rules to remember:

  • declare(strict_types=1); must be the very first statement in the file — only comments may come before it. Any output ahead of it (including plain HTML outside <?php ... ?>) causes a fatal error. This is why it can't be used in a page like processorder.php, which starts with <!DOCTYPE html> before the PHP block.

  • It applies per file, and it governs calls made from that file — not the file where the function happens to be defined.

  • It affects function arguments and return values (including PHP's built-in functions, e.g. strlen(123) is a TypeError in strict mode but returns 3 in weak mode). It does not change operators: "10" + "20" still juggles to 30 exactly as in the Lab #1 example.

Why use it: strict mode catches type mistakes immediately, at the exact line where the wrong type was passed, instead of letting PHP silently convert the value and produce a surprising result later. The tradeoff is less flexibility — data arriving as strings (like everything in $_POST) must be cast explicitly, e.g. add((int) $_POST['tiresqty'], 10), which ties directly back to type casting from last week.

Typed Function Example — addNumbers()

<?php
declare(strict_types=1);

function addNumbers(int $a, int $b): int {
    return $a + $b;
}

echo addNumbers(5, 10);   // 15
echo addNumbers("5", 10); // ❌ TypeError — "5" is a string, and strict mode won't convert it
?>

Anatomy of the function line:

  • int $a, int $b — parameter type declarations: each argument must be an int.

  • : int — the return type declaration: the function must return an int.

  • return $a + $b; — return takes one expression. To send back two values, return an array instead: return [$a, $b];.

Common syntax mistakes when typing this out (the garbled version function addNumbers(int$a, int$b, { return $a, $b):

  1. No space between the type and the variable (int$a instead of int $a).

  2. The parameter list is never closed — the ) is missing before {, and there is a stray trailing comma.

  3. return $a, $b — a comma is not valid after return; use + to add the values (or return an array to return both).

  4. Missing ; after the return statement and the closing } of the function.

Why Use Strict Types?

The problem it solves: in the default (weak/coercive) mode, PHP converts values to fit a type declaration, and some of those conversions lose or change information without any warning — 5.5 quietly becomes 5, true quietly becomes 1. The code runs, returns a plausible number, and the bug surfaces much later (a wrong order total, say) far from where it started.

Reasons to use it:

  1. Bugs show up immediately — the TypeError points at the exact call that passed the wrong type.

  2. No silent data loss — values are never truncated, rounded, or reinterpreted behind your back.

  3. The function signature becomes a contract — int $a, int $b): int states precisely what goes in and what comes out, which makes the code self-documenting.

  4. Predictable behavior — the same input always either works exactly or fails loudly, instead of depending on PHP's conversion rules.

  5. Familiar to C/C++/Java developers — it brings PHP closer to the statically typed languages covered in the array comparison earlier.

  6. Better tooling — editors and static-analysis tools can catch type mistakes before the code ever runs.

Tradeoffs:

  • Data that arrives as strings (everything in $_POST / $_GET) must be converted explicitly with a cast, e.g. addNumbers((int) $_POST['qty'], 10).

  • It only covers function arguments and return values — operators like + still juggle types ("10" + "20" is still 30).

  • It is per file, so a project needs the declaration at the top of each file.

Strict Types — Everything to Know

  • Two typing modes: weak/coercive (the default — PHP converts when it safely can) and strict (declare(strict_types=1); — the type must match exactly).

  • Scalar type declarations (int, float, string, bool) and strict_types were introduced together in PHP 7.0.

  • Other declarable types: array, callable, iterable, object, class names, mixed (PHP 8.0), nullable types (?int — an int or null), and union types (int|string, PHP 8.0). Return types additionally allow void.

  • The one exception in strict mode: an int may be passed where a float is expected, because the conversion is lossless.

  • Scope: strict_types affects calls made from the file that declares it. A function's return type is checked using the mode of the file where the function is defined.

  • Placement: it must be the first statement in the file (only comments may precede it); output before it, including HTML outside <?php, is a fatal error.

  • It cannot be turned on or off mid-file — it is a file-level directive, not a runtime setting.

  • Failure mode: a mismatch throws TypeError, which can be caught with try/catch.

  • What it does not affect: arithmetic and string operators, echo, casts like (int), or settype() — it only governs function and method arguments and return values (built-in PHP functions included, e.g. strlen(123) is a TypeError in strict mode).

  • Performance: it is not a speed feature — the benefit is correctness.

Default Argument Values — setHeight()

Definition — default value: a default value is the value a parameter automatically takes when the caller does not supply that argument. It is written in the function's parameter list with =, for example $minheight = 50. A parameter with a default becomes optional; a parameter without one is required.

function required($x)       { echo $x; }
function optional($x = 50)  { echo $x; }

optional();   // 50 — default used
required();   // ❌ ArgumentCountError: Too few arguments to function required()

In short: the default is a fallback. It is used only when the argument is missing, and any value passed in overrides it.

<?php
function setHeight(int $minheight = 50) {
    echo "The height is : $minheight <br>";
}

setHeight(350);
setHeight();     // no argument passed — uses the default value of 50
setHeight(135);
setHeight(80);
?>

Output in the browser:

The height is : 350
The height is : 50
The height is : 135
The height is : 80

What is happening, line by line:

  • function setHeight(int $minheight = 50) — declares a function with one parameter, $minheight, which must be an int. The = 50 gives the parameter a default value, which makes it optional.

  • echo "The height is : $minheight <br>"; — a double-quoted string, so $minheight is interpolated (replaced by its value), and <br> moves the browser to the next line.

  • setHeight(350); — an argument is passed, so $minheight is 350. The default is ignored.

  • setHeight(); — no argument passed, so PHP falls back to the default and $minheight is 50. This is the line the example exists to show.

  • setHeight(135); and setHeight(80); — an argument is passed each time, so each call uses its own value.

Key idea: a default value is only used when the caller leaves that argument out. Any value the caller does pass always wins.

Rules to remember:

  • Optional parameters (those with defaults) should come after the required ones. Writing function f($a = 1, $b) is deprecated in PHP 8.

  • A default must be a constant value (a number, string, array, null, a constant) — not the result of a function call or a variable.

  • It combines with type declarations (int $minheight = 50) and with strict types: setHeight("350") throws a TypeError in strict mode, while the default 50 is used without any problem when the argument is omitted.

Why it is useful: it lets one function cover the common case with no arguments (setHeight()) while still allowing a custom value (setHeight(350)), and it avoids writing a second version of the function.

Update — the version written in class:

<?php

    echo "The height is: $minheight <br>";
}

Output in the browser:

Differences from the typed version above:

  • There is no int type declaration on $minheight, so the function accepts any type. setHeight("tall") would print The height is: tall with no error, whereas the int version would throw a TypeError. Adding int (as in int $minheight = 50) is what makes the type checks — and strict mode — apply to this function.

  • Only two calls are made, which is all that is needed to show the idea: setHeight(350) passes a value, and setHeight() passes nothing, so the default 50 is used.

  • The file has no closing ?>. That is valid — PHP does not require it at the end of a file, and leaving it off is common practice for files that contain only PHP.

Variable Scope — Local, Global, and Static

Scope is the part of a program where a variable can be seen and used. PHP has three scopes you need to know.

In brief:

ScopeDeclaredVisibleLifetime
LocalInside a functionOnly inside that functionCreated when the function runs, destroyed when it ends
GlobalOutside any functionOutside functions — and inside only through global or $GLOBALSThe whole script
StaticInside a function, with staticOnly inside that functionKeeps its value between calls for the rest of the script

Local scope

A variable created inside a function exists only inside that function. Function parameters are local too.

<?php
function localOnly() {
    $y = 99;        // local to localOnly()
    echo $y;        // 99
}

localOnly();
echo $y;            // ⚠️ Warning: Undefined variable $y — it does not exist out here
?>

  • The variable is created each time the function is called and thrown away when it returns, so nothing carries over to the next call.

  • Two functions can each use a variable with the same name without interfering with each other, and a local $x does not touch a global $x — they are separate variables.

$x = "global x";
function shadow() {
    $x = "local x";  // a brand-new local variable, unrelated to the global $x
    echo $x;          // local x
}
shadow();
echo $x;              // global x — unchanged

Global scope

A variable created outside every function is global. Unlike C/C++ and JavaScript, a PHP function cannot see global variables automatically — inside the function it is treated as if it did not exist.

<?php
$x = 5;                       // global

function noAccess() {
    var_dump(isset($x));      // bool(false) — the global $x is invisible in here
}
noAccess();
?>

There are two ways to reach a global from inside a function, and both work on the real global variable, not a copy:

<?php
$x = 5;

function withGlobal() {
    global $x;      // 1) the global keyword brings $x into the function
    $x++;
    return $x;
}
echo withGlobal(); // 6
echo $x;           // 6 — the global itself was changed

function viaGlobals() {
    $GLOBALS['x'] += 10; // 2) $GLOBALS is an array holding every global variable
}
viaGlobals();
echo $x;           // 16
?>

  • Superglobals such as $_POST, $_GET, and $GLOBALS are the exception: they are available in every scope automatically, which is why $_POST['tiresqty'] works inside any function.

  • Best practice: avoid relying on globals. A function that silently reads or changes a global has a hidden dependency, which makes bugs hard to track down. Pass values in as parameters and send results back with return.

Static scope

A static variable is local to its function, but it is not destroyed when the function ends — it remembers its value for the next call. It is initialized only once, the first time the line runs.

<?php
function counter() {
    static $n = 0;   // set to 0 on the first call only
    $n++;
    echo $n . " ";
}
counter(); counter(); counter();   // 1 2 3

function plain() {
    $n = 0;          // reset to 0 on every call
    $n++;
    echo $n . " ";
}
plain(); plain(); plain();         // 1 1 1
?>

  • The only difference between the two functions is the word static — that is what keeps $n alive between calls.

  • It is still not visible outside the function; it is a local variable with a longer memory.

  • Typical uses: counters, running totals, and caching a result so it is calculated once.

Example from class — myTest():

<?php

Related: passing outer variables into closures

An anonymous function has its own local scope too. It receives outer variables explicitly with use, while an arrow function (fn) captures them automatically — in both cases as a copy of the value.

$total = 100;
$f = function() use ($total) { return $total + 1; };
$g = fn() => $total + 2;
echo $f();   // 101
echo $g();   // 102

Classes in PHP — and How Scope Works Inside Them

PHP fully supports object-oriented programming. Functions are what has been covered so far, so scope was shown with functions — classes build on the same ideas.

Definitions:

TermMeaning
ClassA blueprint that describes what a kind of object has and can do
ObjectOne actual thing built from a class, created with new
PropertyA variable that belongs to a class/object
MethodA function that belongs to a class/object
$thisInside a method, the object the method is currently running on
ConstructorThe special method __construct(), which runs automatically when an object is created
VisibilityWho may access a property or method: public (anywhere), private (only inside the class), protected (the class and its subclasses)
staticA property or method that belongs to the class itself, shared by every object, instead of to one object
<?php
class Counter {
    public int $count = 0;                  // property — each object has its own
    public static int $instances = 0;       // static property — one copy shared by the class
    private int $secret = 7;                // private — only code inside the class can use it
    const MAX = 10;                         // class constant

    public function __construct() {         // constructor — runs on `new`
        self::$instances++;
    }

    public function add(): void {           // method
        $local = 1;                         // local variable — same rules as in any function
        $this->count += $local;             // $this = the object this method was called on
    }

    public static function describe(): string {   // static method
        return "Counter class, max " . self::MAX;
    }
}

$a = new Counter();
$b = new Counter();
$a->add(); $a->add(); $b->add();

echo $a->count . " " . $b->count;   // 2 1 — each object keeps its own count
echo Counter::$instances;           // 2 — the static property is shared
echo Counter::describe();           // Counter class, max 10
echo $a->secret;                    // ❌ Error: Cannot access private property Counter::$secret
?>

Scope rules inside a class:

  • Local variables: a method is just a function, so variables created inside it (like $local) are local and disappear when it returns.

  • Properties are not globals: they are reached through the object with $this->count (or $a->count from outside), and each object has its own copy.

  • Globals are still not visible inside a method — a method needs global or $GLOBALS, exactly like a plain function. In a test, isset($x) for a global $x was false inside a method.

  • static has a second meaning in classes: inside a function, static $n keeps a value between calls; on a class property or method, static means it belongs to the class itself and is accessed with ClassName:: or self:: instead of $this->.

  • Visibility adds a layer of scope: private and protected restrict who may use a property or method, which is how a class protects its own data.

Q2 — max_function.php

<?php
function maxNum($a, $b) {
    if ($a > $b) {
        return $a;
    } else {
        return $b;
    }
}

echo "Max of 10 and 25 is: " . maxNum(10, 25) . "<br>";   // 25

3–5. What runs, in order: line 3 prints "Before (global): 10"; line 4 calls the function, which sets the outer $num to 20; line 5 prints "After (global): 20". The change stays after the function ends because the function edited the original, not a local copy.

Other ways to change a global

PHP stores every global variable in the $GLOBALS array, so this does the same thing with no global keyword:

function modifyNumGlobal() {
    $GLOBALS['num'] = $GLOBALS['num'] + 10;
}

The global keyword works, but many developers avoid it because any function can quietly change your variables. The usual better approach is to pass the value in and return the new one:

function addTen($n) {
    return $n + 10;
}
$num = addTen($num);   // $num is now 20

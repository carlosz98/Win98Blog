Automatic Type Conversion (Type Juggling)

PHP is a loosely typed language — you never have to declare a variable's type up front, and PHP will automatically convert a value from one type to another when the context calls for it. This is called type juggling (mentioned briefly back in Week 2 when adding up $tireqty + $oilqty + $sparkqty, even though those values arrived from $_POST as strings).

How it works: when an operator expects a certain type but gets a different one, PHP converts the value on the fly instead of throwing an error.

$quantity = "5";      // a string
$price = 10;           // an integer

$total = $quantity * $price;
echo $total;            // 50
echo gettype($total);   // "integer"

Here, $quantity starts as the string "5". Because it's used with the multiplication operator *, PHP automatically converts it to the integer 5 behind the scenes, does the math, and the result ($total) comes out as an integer — 50 — even though one of the original values was text.

Where this shows up in our own code: exactly this happened with the order form's $_POST values:

$tireqty = $_POST['tiresqty'];   // arrives as a STRING, e.g. "3"
$totalqty = $tireqty + $oilqty + $sparkqty;   // PHP converts each to a number to add them

Important distinction — this is different from settype(): type juggling happens automatically and temporarily, just for that one operation — the original variable's type doesn't actually change. settype() (covered earlier), by contrast, permanently converts the variable itself.

$quantity = "5";
$total = $quantity * 10;   // juggling: $quantity is still the string "5" after this
echo gettype($quantity);   // "string" — unchanged

Key takeaways:

  • PHP automatically converts between types when an operation needs it — this is type juggling.

  • It's temporary and happens only for that operation; the original variable keeps its original type.

  • This is why form data (always strings from $_POST) can be used directly in math without manually converting it first.

Quick Review: define()

Already covered in Week 2 (used for tireprice, oilprice, sparkprice), but worth a quick refresher example:

define("PI", 3.14);
echo PI;          // 3.14
echo PI * 2;       // 6.28

  • define("PI", 3.14); creates a constant named PI holding the value 3.14.

  • Used without a $ — unlike a regular variable, a constant is referenced by name alone.

  • Once defined, its value can't be changed later in the script — attempting to redefine PI would trigger a warning/error, which is exactly the point: constants protect fixed values (like a mathematical constant, or a tax rate, or item prices) from being accidentally overwritten somewhere else in the code.

Constants vs. Variables:

VariableConstant
Declared with$name = value;define("NAME", value);
Referenced with$name (dollar sign required)NAME (no dollar sign)
Naming conventionusually snake_case or camelCase, lowercaseusually ALL_CAPS by convention
Value can change later?YesNo — fixed for the rest of the script
Case-sensitive?Yes, alwaysYes, by default
$radius = 5;
define("PI", 3.14);

$area = PI * ($radius * $radius);
echo $area;   // 78.5

$radius = 10;   // fine — variables can be reassigned
// define("PI", 3.15);   // NOT allowed — PI is already defined

Rule of thumb: if the value should never change during the script (a price, a tax rate, a mathematical constant like PI), use a constant. If the value is expected to change (user input, a running total, a loop counter), use a variable.

Checking Variables: isset(), unset(), empty()

Three built-in functions for working with whether a variable exists and what it holds.

isset($var) — checks whether a variable exists and is not null. Returns true or false.

$name = "Carlos";
echo isset($name);        // true (1)

$nothing = null;
echo isset($nothing);      // false

echo isset($undeclared);   // false — never even set

📝 Connects to class: this is exactly the function used in the todo app to check which button was pressed — if (isset($_POST['submit'])) checks whether the "Add" button's data actually arrived with the request.

unset($var) — destroys a variable entirely, as if it was never declared. After this, isset() on that variable returns false again.

$name = "Carlos";
echo isset($name);   // true

unset($name);
echo isset($name);   // false
// echo $name;       // would trigger a warning — the variable no longer exists

empty($var) — checks whether a variable is "empty" — meaning it doesn't exist, or it holds a falsy value: "", 0, "0", null, false, or an empty array []. Returns true or false.

$tireqty = "";
var_dump(empty($tireqty));   // true — empty string

$tireqty = "0";
var_dump(empty($tireqty));   // true — "0" counts as empty

$tireqty = "3";
var_dump(empty($tireqty));   // false — has a real value

var_dump(empty($undeclared)); // true — doesn't exist

Quick comparison:

FunctionCheckstrue when
isset($var)Does it exist and isn't null?Variable is declared with a real (non-null) value
unset($var)(not a check — an action)Deletes the variable
empty($var)Is it "nothing"?Doesn't exist, OR holds "", 0, "0", null, false, or []

⚠️ Gotcha: empty("0") is true — the string "0" counts as empty in PHP, even though it's not actually blank. This has tripped people up when validating form input like a quantity of 0.

Key takeaways:

  • isset() — does this variable exist and have a non-null value?

  • unset() — delete a variable completely.

  • empty() — broader check than isset(); also catches "technically set but effectively blank" values like "" or 0.

var_dump()

What it does: prints a variable's value, data type, and length/size all at once — much more detailed than echo or even gettype(). It already showed up above in the empty() examples; here's what it's actually doing.

$name = "Carlos";
var_dump($name);
// string(6) "Carlos"

$age = 27;
var_dump($age);
// int(27)

$price = 9.99;
var_dump($price);
// float(9.99)

$isStudent = true;
var_dump($isStudent);
// bool(true)

$nothing = null;
var_dump($nothing);
// NULL

Reading the output: string(6) "Carlos" means — this is a string, it's 6 characters long, and its value is "Carlos". Every type gets this same treatment: type name, size/length where relevant, then the actual value.

Where it's genuinely useful — arrays:

$order = ["tires" => 3, "oil" => 4, "sparkplugs" => 4];
var_dump($order);

/*
array(3) {
  ["tires"]=>
  int(3)
  ["oil"]=>
  int(4)
  ["sparkplugs"]=>
  int(4)
}
*/

This is where var_dump() shines — it shows every key, every value, and every value's type inside a complex structure like an array, all in one call.

var_dump() vs. gettype() vs. echo:

FunctionShows
echoJust the value (converted to a displayable string)
gettype($x)Just the type, as a string ("string", "integer", etc.)
var_dump($x)Type and value and length, for one variable or a whole array/object at once

Key takeaways:

  • var_dump() is a debugging tool — like gettype(), not typically left in a finished app.

  • It shows type, size, and value together, which makes it especially useful for inspecting arrays or figuring out why a comparison isn't behaving as expected.

  • Use it any time you're not 100% sure what a variable actually contains.

echo vs. print

Both output text to the page, but differ slightly:

echoprint
Multiple arguments?Yes — echo "a", "b";No — only one value
Returns a value?NoYes — always returns 1
SpeedMarginally fasterMarginally slower
echo "Hello", " ", "World";   // works — multiple arguments
// print "Hello", " ", "World";  // ❌ error — print takes only one argument

print "Hello World";           // fine — single argument

In practice: functionally interchangeable for simple output. echo is the more common convention — and what we've used in every example so far (the order form, the todo app, etc.).

Why print "returns" 1 — and what that actually means:

Output (what shows on the page) and a function's return value (what it hands back to whatever called it) are two separate things. print always returns 1 after it runs — that 1 isn't displayed unless you explicitly do something with it, like assign it or echo it:

$result = print "Hello";
// Output shown on page: Hello
// $result now holds: 1  (print's return value — not shown unless echoed)

echo $result; // THIS actually prints "1" to the page

echo, by contrast, has no return value at all — it can't be assigned:

$result = echo "Hello"; // ❌ parse error — echo cannot be used in an expression

This is why print's return value lets it (rarely) be used inside a larger expression, while echo never can — though in everyday code this distinction almost never matters.

echo with HTML tags:

echo just outputs whatever string you give it — including HTML tags — and the browser renders that string as actual HTML, not as plain text. This is the core of how PHP mixes with a webpage: build the HTML as a string, echo it, and the browser displays it normally.

echo "<h1>Order Confirmation</h1>";
echo "<p>Thank you for your order!</p>";

Variables can be interpolated right inside the tags, same as any other double-quoted string:

$name = "Carlos";
echo "<h1>Hello, $name!</h1>";
echo "<p>Your order total is $" . number_format($total, 2) . "</p>";

Practice: Declaring Variables of Different Types

A script declaring and initializing five variables — string, integer, float, boolean, and NULL — then printing them with both echo and var_dump():

<?php
// Declaring and initializing five variables of different types
$studentName = "Carlos";      // string
$age = 27;                    // integer
$gpa = 3.85;                  // float (decimal)
$isEnrolled = true;           // boolean
$middleName = NULL;           // NULL

// Printing values with echo
echo "Name: " . $studentName . "<br>";
echo "Age: " . $age . "<br>";
echo "GPA: " . $gpa . "<br>";
echo "Enrolled: " . $isEnrolled . "<br>"; // true prints as "1", false prints as "" (empty)
echo "Middle Name: " . $middleName . "<br>"; // NULL prints as nothing

// Inspecting values + types with var_dump()
var_dump($studentName);
var_dump($age);
var_dump($gpa);
var_dump($isEnrolled);
var_dump($middleName);
?>

Notes on the output:

  • echo on a boolean shows 1 for true and nothing at all for false — echo can't display true/false as words.

  • echo on NULL prints nothing (an empty string) — no error, just blank output.

  • var_dump() is the better debugging tool here — it shows the real type and value for every variable, including bool(true) and NULL explicitly, instead of hiding them like echo does.

Key takeaways:

  • Every change in the todo app triggers a new request, PHP running again, and updated HTML coming back.

  • CRUD = Create, Read, Update, Delete — the four core operations most data-driven apps are built on.

  • The todo list is the standard "hello world" for showing how a technology handles CRUD.

for and foreach Loops

for loop — used when you know how many times you want to repeat something, or need a counter. It has three parts: a starting value, a condition to keep looping, and what happens after each pass.

for ($i = 1; $i <= 5; $i++) {
    echo "Count: " . $i . "<br>";
}

Output:

Count: 1
Count: 2
Count: 3
Count: 4
Count: 5

The three parts, in order every time the loop runs:

  1. $i = 1 — runs once, before the loop starts (sets the starting point)

  2. $i <= 5 — checked before every pass; loop stops as soon as this is false

  3. $i++ — runs after every pass (increases $i by 1)

foreach loop — used specifically to go through every item in an array, one at a time, without needing to manage a counter yourself.

$fruits = ["Apple", "Banana", "Cherry"];

foreach ($fruits as $fruit) {
    echo $fruit . "<br>";
}

Output:

Apple
Banana
Cherry

foreach automatically walks through the array from start to finish — $fruit takes on each value in turn, no index tracking needed.

foreach with keys — for associative arrays (arrays with named keys instead of numeric ones), foreach can grab both the key and the value at once:

$prices = ["Tire" => 100, "Oil" => 20, "Spark Plug" => 4];

foreach ($prices as $item => $price) {
    echo $item . ": $" . $price . "<br>";
}

Output:

Tire: $100
Oil: $20
Spark Plug: $4

for vs. foreach — when to use which:

forforeach
Best forCounting, repeating a fixed number of timesLooping through every item in an array
Needs a counter variableYes (you manage it)No (handled automatically)
Works on arraysYes, but needs index trackingYes — built for this
Common usefor ($i = 0; $i < 10; $i++)foreach ($array as $value)

In practice: this connects directly back to the order form from Week 2 — instead of manually writing $_POST['tiresqty'], $_POST['oilqty'], $_POST['sparkqty'] separately, a foreach over an array of item names could loop through and process each one the same way, which is the more scalable approach once there are many items instead of just three.

for Loop — Deeper Dive

Definition: a for loop repeats a block of code a specific number of times, controlled by a counter variable. It's the go-to loop when you know (or can calculate) exactly how many times something needs to run.

Syntax:

for (initialization; condition; increment) {
    // code to repeat
}

Example — counting up:

for ($i = 1; $i <= 5; $i++) {
    echo $i . "<br>";
}
// Output: 1 2 3 4 5 (each on its own line)

Example — counting down:

for ($i = 5; $i >= 1; $i--) {
    echo $i . "<br>";
}
// Output: 5 4 3 2 1

Example — stepping by more than 1:

for ($i = 0; $i <= 10; $i += 2) {
    echo $i . "<br>";
}
// Output: 0 2 4 6 8 10 (even numbers only)

Example — looping through an array by index:

$items = ["Tires", "Oil", "Spark Plugs"];

for ($i = 0; $i < count($items); $i++) {
    echo $items[$i] . "<br>";
}
// Output: Tires  Oil  Spark Plugs

count($items) returns the number of elements in the array (3 here), so the loop automatically stops at the last index regardless of array size — no need to hardcode the number of items.

Example — nested for loop (a loop inside a loop, useful for grids/tables):

for ($row = 1; $row <= 3; $row++) {
    for ($col = 1; $col <= 3; $col++) {
        echo "($row,$col) ";
    }
    echo "<br>";
}
// Output:
// (1,1) (1,2) (1,3)
// (2,1) (2,2) (2,3)
// (3,1) (3,2) (3,3)

The inner loop completes all its passes for every single pass of the outer loop — that's why the pattern repeats in rows.

Common mistakes to watch for:

  • Forgetting the increment ($i++) — causes an infinite loop, since the condition never becomes false.

  • Off-by-one errors — using < instead of <= (or vice versa) skips or adds an extra iteration. With arrays specifically, $i < count($items) is correct; $i <= count($items) would try to access one index past the end and cause an error.

switch Statement

Definition: a switch statement checks one variable against several possible values and runs the code block that matches — a cleaner alternative to a long if/else if/else chain when you're comparing the same variable against many fixed options.

Syntax:

switch (variable) {
    case value1:
        // code
        break;
    case value2:
        // code
        break;
    default:
        // code if nothing matched
}

Example — rewriting the order form's find dropdown check with switch instead of if/else if:

$find = $_POST['find'];

switch ($find) {
    case 'a':
        echo "<p>Regular Customer</p>";
        break;
    case 'b':
        echo "<p>Customer referred by TV advert</p>";
        break;
    case 'c':
        echo "<p>Customer referred by phone directory</p>";
        break;
    case 'd':
        echo "<p>Customer referred by word of mouth</p>";
        break;
    default:
        echo "<p>We do not know how this customer found us</p>";
}

Same logic, same output as the if/else if version from earlier — switch is just a different way to write it, and reads a little cleaner once there are more than 2-3 options to check against a single variable.

break is critical: without break, PHP doesn't stop at the matching case — it keeps running every case below it too, a behavior called "fall-through."

$grade = 'B';

switch ($grade) {
    case 'A':
        echo "Excellent<br>";
    case 'B':
        echo "Good<br>";
    case 'C':
        echo "Passing<br>";
    default:
        echo "Grade recorded<br>";
}
// Output (no breaks):
// Good
// Passing
// Grade recorded

Even though only 'B' matched, execution fell through into 'C' and default too because there were no break statements to stop it. Adding break; after each case fixes this and produces only Good.

Intentional fall-through is sometimes used on purpose, to group multiple values under one action:

$day = "Sat";

switch ($day) {
    case "Sat":
    case "Sun":
        echo "Weekend<br>";
        break;
    default:
        echo "Weekday<br>";
}
// Output: Weekend

Here "Sat" and "Sun" share the same case block on purpose — since "Sat" has no break, it falls through into the "Sun" case's code, which is exactly what's wanted.

switch vs. if/else if:

switchif/else if
Best forOne variable checked against many fixed valuesAny condition, including ranges (>, <) and multiple variables
Comparison typeLoose (==), alwaysWhatever operator you write (==, ===, <, etc.)
Needs breakYes, or it falls throughNot applicable — each branch is independent
ReadabilityCleaner with many options on one variableCleaner for complex/mixed conditions

exit

Definition: exit immediately stops the PHP script from running any further — nothing after it executes, no matter what code comes next in the file. die() is an alias for exit (they do exactly the same thing; die reads a little more literally for error cases).

Syntax:

exit; // stops the script here, no message
exit(); // same thing, with parentheses
exit("message"); // stops the script AND prints a message first

Basic example:

echo "This will print.<br>";
exit("Stopping here.<br>");
echo "This will NEVER print.<br>";

Output:

This will print.
Stopping here.

The third line never runs — exit() halts the script the moment it's reached, so nothing after it in the file matters, even if it's valid code.

Common real use — guarding against missing data:

if (!isset($_POST['tiresqty'])) {
    exit("Error: no order data received.");
}

// rest of processorder.php only runs if the check above passed
$tireqty = $_POST['tiresqty'];

This is a safer version of the empty-order check from earlier — instead of just printing a message and letting the rest of the script keep running (and possibly erroring on missing $_POST data), exit() stops everything immediately so nothing broken runs afterward.

exit vs. return: return only exits the current function (or included file) and hands control back to whatever called it; exit shuts down the entire script everywhere, even inside a deeply nested function call. Use return for normal function flow, exit only when something is wrong enough that continuing the whole page doesn't make sense.

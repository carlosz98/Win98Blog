PHP Integers (Review)

Integer (int): a whole number — no decimal point, positive or negative.

$age = 27;
$temperature = -10;

Storage — integers vs. floats:

intfloat
RepresentsWhole numbers onlyNumbers with decimals
PrecisionExact — stored as the exact value, no roundingApproximate — stored in a format (IEEE 754) that trades exactness for being able to hold a huge range of values
Size/rangePlatform-dependent, but typically 64-bit on modern systems (roughly ±9.2 quintillion)Also platform-dependent, usually a 64-bit "double" — same size as int on most systems, but spent on range + decimals instead of whole-number precision
Common issueNone — math stays exactRounding errors can creep in, since not every decimal value can be represented exactly in binary

Why float imprecision happens — a classic example:

$result = 0.1 + 0.2;
echo $result; // 0.3, looks fine...
var_dump($result == 0.3); // bool(false) !

Even though it displays as 0.3, internally PHP (like virtually every programming language) stores 0.1 and 0.2 as binary floating-point approximations, not the exact decimal values — so the actual sum is something like 0.30000000000000004. This is why comparing floats with == is risky; it's a hardware/storage limitation, not a PHP bug.

In practice: use int whenever you're counting whole things (quantities, ages, IDs) — it's exact and has no rounding risk. Use float for money, measurements, or anything with decimals, but be cautious comparing floats directly with ==.

Example — int × float:

<?php
$a = 5;       // int
$b = 5.34;    // float
$c = "25";    // string (numeric string)

echo $a . "<br>"; // 5
echo $b . "<br>"; // 5.34
echo $c . "<br>"; // 25

$r = $a * $b;
echo $r . "<br>"; // 26.7
var_dump($r);      // float(26.7)
?>

Output:

5
5.34
25
26.7
float(26.7)

Here's what's different between the two: echo just prints the raw value as text — $a, $b, and $c all come out looking like plain numbers on the page, with no visible distinction between the int, float, and string types. You genuinely can't tell from the echo output alone that $c is a string and not a number — they all just look like 5, 5.34, 25.

var_dump() is the one that reveals the actual type underneath — float(26.7) tells you explicitly that $r is a float, something plain echo output can never show you.

Why a "whole number" result can still be a float:

$a = 4;      // int
$b = 2.5;    // float

$r = $a * $b;
var_dump($r); // float(10)

Mathematically 4 * 2.5 = 10, a clean whole number — but PHP still reports it as float(10), not int(10). The result type is decided by the types of the operands, not by what the final value looks like: if either operand is a float, the result is always a float, even when that float lands exactly on a whole number with nothing after the decimal. PHP never "downgrades" a float back to an int just because the decimal came out to .0.

Multiplying an int ($a) by a float ($b) automatically converts the result to a float — PHP always "upgrades" the result to whichever type can hold more precision, so int * float → float, never the other way around. $c isn't used in the math here, but it's a good example of a numeric string sitting unused — if it had been included in the multiplication, PHP would auto-convert it to a number first (type juggling, covered earlier).

Integer Literal Formats — Decimal, Hexadecimal, Octal

<?php
$decimal = 100;      // base 10 — the normal way, no prefix
$hex = 0x64;          // base 16 — prefixed with 0x, digits 0-9 and A-F
$octal = 0144;         // base 8 — prefixed with a leading 0, digits 0-7

echo $decimal . "<br>"; // 100
echo $hex . "<br>";     // 100
echo $octal . "<br>";   // 100
?>

All three lines above represent the same value, 100 — just written in different number bases. PHP converts all of them to the same internal integer; echo always displays the decimal (base 10) form regardless of which format was used to write it.

FormatBasePrefixExampleEquals (decimal)
Decimal10none100100
Hexadecimal160x0x64100
Octal8leading 00144100

Why these exist: decimal is the everyday format. Hexadecimal shows up constantly in things like color codes (#FF0000 in CSS) and memory addresses. Octal is rarer today but was historically used for file permissions (Unix chmod 0755, for example).

Common mistake: a leading 0 on a number that wasn't meant to be octal — $num = 0123; is actually interpreted as octal (equal to 83 in decimal), not as the literal number "one hundred twenty-three." This trips people up if a number is zero-padded for formatting and the leading zero accidentally signals octal instead.

Integer Limits — PHP_INT_MAX, PHP_INT_MIN, PHP_INT_SIZE

<?php
echo PHP_INT_MAX . "<br>"; // 9223372036854775807
echo PHP_INT_MIN . "<br>"; // -9223372036854775808
echo PHP_INT_SIZE . "<br>"; // 8
?>

PHP has three built-in constants describing the limits of the int type on the current system:

ConstantWhat it tells youTypical value (64-bit system)

PHP_INT_MINThe smallest (most negative) integer PHP can hold-9223372036854775808

That's why they're constants looked up at runtime rather than numbers to hardcode — the actual limit isn't guaranteed to be the same everywhere.

What happens past the limit: PHP doesn't error — it automatically converts the number to a float instead, since floats can represent a much larger range (just with less precision):

$overflow = PHP_INT_MAX + 1;
var_dump($overflow); // float(9.2233720368548E+18)

is_int()

Definition: is_int() checks whether a variable's value is of type int, returning true or false. Part of the same is_*() family covered earlier (is_array(), is_double(), etc.) — a quick way to check a type without needing the full output of gettype() or var_dump().

<?php
$a = 5;       // int
$b = 5.34;    // float
$c = "25";    // string

var_dump(is_int($a)); // bool(true)
var_dump(is_int($b)); // bool(false) -- it's a float, not an int
var_dump(is_int($c)); // bool(false) -- it's a string, even though it "looks" numeric
?>

Key point — is_int() checks the actual type, not whether something looks like a number: "25" is a numeric string, and PHP will happily do math with it (type juggling), but is_int("25") still returns false because the variable's real, stored type is string, not int. is_numeric() is the function that would return true for a string like "25" — is_int() is stricter and only accepts the real thing.

Common use — inside a condition, as a guard:

if (is_int($tireqty)) {
    echo "Valid quantity.<br>";
} else {
    echo "Quantity must be a whole number.<br>";
}

This is the kind of check that's useful before doing math with form data — though worth noting, $_POST values always arrive as strings, so is_int($_POST['tiresqty']) would actually be false even for a valid number like "5"; is_numeric() or converting with (int) first would be the more realistic check in that situation.

    echo "Equal enough.<br>";
} else {
    echo "Not equal.<br>";
}
// Output: Equal enough.

is_float()

Definition: is_float() checks whether a variable's value is of type float, returning true or false. (is_double() is an alias for the exact same thing — same reasoning as gettype() returning "double" instead of "float".)

<?php
$a = 5;       // int
$b = 5.34;    // float
$c = "25";    // string

var_dump(is_float($a)); // bool(false) -- it's an int, not a float
var_dump(is_float($b)); // bool(true)
var_dump(is_float($c)); // bool(false) -- it's a string
?>

Same logic as is_int() from earlier: is_float() checks the variable's actual stored type, not whether the value merely looks like a decimal. A numeric string like "5.34" would still return false from is_float(), the same way "25" returned false from is_int().

PHP INF (Infinity) and NAN (Not a Number)

Both are special float values — not errors, not exceptions — that PHP returns when a calculation goes beyond what a normal number can represent.

<?php
$big = PHP_FLOAT_MAX * 2; // multiplying past the max float
var_dump($big);             // float(INF)

$invalid = sqrt(-1);        // square root of a negative number
var_dump($invalid);         // float(NAN)

echo $big . "<br>";         // INF
echo $invalid . "<br>";     // NAN
?>
INFNAN
MeansA number larger than the maximum representable float (overflow)The result of a math operation that has no valid numeric answer
Common causeDividing by a very small number, multiplying past PHP_FLOAT_MAX, 1/0 style overflowsqrt(-1), 0/0, INF - INF, invalid math
Typefloatfloat
Check withis_infinite()is_nan()

Checking for them:

var_dump(is_infinite($big));    // bool(true)
var_dump(is_nan($invalid));     // bool(true)
var_dump(is_finite($big));      // bool(false) -- opposite of is_infinite()

Important quirk — NAN is never equal to anything, including itself:

$x = NAN;
var_dump($x == NAN); // bool(false) !!
var_dump($x === NAN); // bool(false) !!

This isn't a bug — it's standard IEEE 754 floating-point behavior (same spec that governs how all floats are stored, from earlier). Since NAN represents "not a valid number," it's defined to never equal any value, not even another NAN. This is exactly why is_nan() exists — it's the only reliable way to check for it; == NAN or === NAN will always silently return false, even when the variable genuinely holds NAN.

Strings — Double vs. Single Quotes (Review)

<?php
$x = "john";

echo "Hello $x"; // Hello john
echo 'Hello $x'; // Hello $x
?>

The difference comes down to double quotes vs. single quotes:

  • Double quotes ("Hello $x") — PHP scans the string for variables and replaces them with their actual value. This is called string interpolation. $x inside the double-quoted string gets swapped out for "john", producing Hello john.

  • Single quotes ('Hello $x') — PHP treats everything inside as literal text, exactly as typed, with no variable substitution. $x is just the two characters $ and x sitting in the string — it prints exactly as written: Hello $x.

Not a bug or inconsistency — it's a deliberate difference in how PHP treats the two quote types. Double quotes do extra work (interpolation, and also escape sequences like \n for a newline); single quotes do none of that and are slightly faster for plain static text since PHP doesn't have to scan them for variables.

String Concatenation (Review)

<?php
$x = "Hello, ";
$y = "World";
$z = $x . $y;

echo $z; // Hello, World
?>

This uses the . (dot) concatenation operator — covered back in Week 2 — which joins two strings together into one, end to end, with no space added automatically unless it's already baked into one of the strings (notice $x has a trailing space: "Hello, ", which is why the result reads naturally instead of coming out as "Hello,World").

Why . instead of +: + is for arithmetic, . is specifically for joining strings. Using + here would trigger type juggling instead of joining — PHP would try to treat $x and $y as numbers, and since neither is numeric, it leads to an error rather than combining the text.

echo $x + $y; // ❌ not what you want — PHP tries math, not text joining
echo $x . $y; // ✅ "Hello, World"

Type Casting

<?php
$x = "42";          // string
$y = (int) $x;       // explicitly cast to int
var_dump($y);         // int(42)

$a = 5;
$b = (float) $a;      // explicitly cast to float
var_dump($b);          // float(5)

$c = 3.99;
$d = (int) $c;         // cast float to int
var_dump($d);           // int(3) -- truncates, does NOT round

$e = 0;
$f = (bool) $e;         // cast to boolean
var_dump($f);            // bool(false)
?>

Definition: type casting is manually, explicitly telling PHP to treat a value as a different type, by putting the target type in parentheses right before the value: (int), (float), (string), (bool), (array).

This is different from type juggling (covered earlier): type juggling is PHP automatically converting types behind the scenes when an operation needs it (like "10" + "20" auto-converting to numbers). Type casting is explicitly forcing the conversion, whether PHP would have done it automatically or not.

CastEffect
(int)Converts to a whole number — truncates any decimal (doesn't round)
(float)Converts to a decimal number
(string)Converts to text
(bool)Converts to true/false (same falsy rules as empty(): 0, "", "0", NULL, empty array → false)
(array)Wraps a non-array value into a single-element array

Important gotcha — (int) truncates, it doesn't round:

var_dump((int) 3.99); // int(3), not int(4)
var_dump((int) 3.01); // int(3)

Even though 3.99 is almost 4, casting to int just chops off everything after the decimal point rather than rounding to the nearest whole number. For actual rounding, use round() — casting is not a substitute for it.

Full list of allowed casts (including aliases):

CastAlso written asConverts to
(int)(integer)Whole number
(float)(double), (real) (deprecated)Decimal number
(string)—Text
(bool)(boolean)true/false
(array)—An array
(object)—An object (a built-in stdClass object, original value stored as a property)
(unset)—NULL (removed in PHP 8 — no longer valid)

The aliases matter because you'll see both styles in different code/textbooks — (integer)/(int), (boolean)/(bool), and (double)/(float) all do exactly the same thing. This connects back to gettype() returning "integer", "boolean", and "double" instead of the short forms — PHP's internal type names are the longer versions, even though the short cast syntax is what's normally used in code.

(array) on a non-array doesn't error — it wraps the value:

$x = "hello";
$arr = (array) $x;
var_dump($arr); // array(1) { [0]=> string(5) "hello" }

(object) similarly wraps a value or array into a generic object, where array keys become object properties:

$data = ["name" => "Carlos", "age" => 27];
$obj = (object) $data;
echo $obj->name; // Carlos

Type Juggling with a Numeric String in Arithmetic

<?php
$a = 10;
$b = 10;
$c = '10'; // numeric string

$total = $a + $b + $c;
echo $total; // 30
var_dump($total); // int(30)
?>

This is type juggling again, not type casting — nobody explicitly wrote (int) $c anywhere, but PHP converts it automatically because + is an arithmetic operator.

Step by step:

  1. $a + $b → 10 + 10 → 20 (both are already int, straightforward)

  2. 20 + $c → PHP sees $c is a string, but checks: is it a numeric string? Yes — '10' contains only digits, so PHP auto-converts it to the integer 10 behind the scenes before doing the math.

  3. 20 + 10 → 30

So even though $c was declared as a string with quotes, PHP silently converts it to a number the moment it's used in an arithmetic operation — same rule as "10" + "20" from Lab #1. The result is an int, not a string.

Limit of this behavior: it only works because '10' looks like a valid number. If $c had been something like '10abc' or 'ten', PHP would either partially convert it (reading only the leading numeric part, with a warning) or treat it as 0, depending on the PHP version — a non-numeric string can't be cleanly juggled into a number the same way.

1. Arrays

Definition: an array is a single variable that holds multiple values at once, instead of one value per variable. PHP arrays are flexible — they can hold any mix of types (strings, ints, floats, even other arrays), and PHP has three main kinds:

PHP is dynamically typed — this is exactly why arrays (and variables generally) don't need a declared type or fixed size up front. The type of each element is decided at runtime based on what's actually stored in it, rather than being locked in ahead of time the way it is in a statically typed language like C/C++ (see the comparison below).

Two ways to declare an array:

$a = array("x", "y", "z"); // built-in array() function — the original syntax
$b = ["x", "y", "z"];       // shorter syntax — elements inside square brackets (modern, preferred)

Three kinds of array: numeric (indexed), associative, and multidimensional — covered individually below.

TypeKeysExample use
Indexed arrayAutomatic numeric keys, starting at 0A simple list of items
Associative arrayCustom, named keys you chooseKey-value data, like a record
Multidimensional arrayAn array containing other arraysTables, grids, nested data

PHP Arrays vs. C/C++ Arrays

// C++ — must declare type and fixed size upfront
int numbers[3] = {10, 20, 30};
numbers[3] = 40; // ❌ undefined behavior — fixed at size 3, no bounds checking

string fruits[3] = {"Apple", "Banana", "Cherry"}; // a SEPARATE array needed for a different type
<?php
// PHP — no declared type, no fixed size
$numbers = [10, 20, 30];
$numbers[] = 40; // ✅ totally fine — array just grows

$mixed = [10, "Banana", 3.14, true]; // one array, four different types, no problem
?>
C / C++PHP
SizeFixed at declaration — can't grow or shrinkDynamic — grows and shrinks freely
TypeMust be one single type (all int, all string, etc.)Can mix any types in the same array
KeysNumeric index only, always sequential from 0Numeric or associative (named) keys, in any order
Bounds checkingNone — writing past the end is undefined behavior, a common source of bugs/crashesSafe — PHP manages the memory and size automatically
What it really isA contiguous block of raw memoryInternally an ordered hash map — PHP's indexed and associative arrays are actually the same underlying structure

Why this matters: in C/C++, the exact size and type need to be planned ahead of time, and growing an array means manually managing memory (often switching to something like std::vector for that flexibility). PHP arrays are flexible by default — no upfront planning needed, which is part of why PHP is easier to write quickly, at the cost of the low-level control and raw performance C/C++ arrays give you.

Indexed Arrays

<?php
$fruits = ["Apple", "Banana", "Cherry"];

echo $fruits[0]; // Apple
echo $fruits[1]; // Banana
echo $fruits[2]; // Cherry

var_dump($fruits);
?>

Each item automatically gets a numeric index starting at 0 — $fruits[0] is the first item, not the second. This is the same $fruits array from the foreach section earlier.

Associative Arrays

Example — representing a person's data:

<?php
$person = [
    "name" => "Carlos",
    "age" => 27,
    "city" => "New York"
];

echo $person["name"] . "<br>"; // Carlos
echo $person["age"] . "<br>";  // 27
echo $person["city"] . "<br>"; // New York
?>

Same idea as $prices above, applied to a different kind of data — a person record. Instead of indexing by position (0, 1, 2), each piece of information has a meaningful name attached to it ("name", "age", "city"), which makes the code much more readable than trying to remember "position 1 is the age."

This is a preview of a very common pattern: representing one real-world "thing" (a person, a product, an order) as a single associative array, with each of its properties as a key — the array version of what a database row or an object would normally hold.

Terminology note — "dictionary": PHP's associative array is the same concept other languages call a dictionary (Python uses that term explicitly), or a hash map/hash table in Java, C++ (std::map/std::unordered_map), and elsewhere — different languages, same underlying idea: a collection of key-value pairs, looked up by key instead of by numeric position. PHP just uses one word, "array," for all three kinds (indexed, associative, multidimensional) rather than having separate names the way other languages do.

Example — using the array() built-in function syntax:

<?php
$ages = array("Joe" => 22, "Alex" => 25, "Peter" => 30);

echo $ages["Joe"]; // 22
?>

Same associative array concept as $person and $prices above, just written with the array() function syntax instead of [], and with names as the keys and ages as the values. $ages["Joe"] looks up the value stored under the key "Joe" and prints 22 — the same lookup pattern used throughout: $arrayName["keyName"].

<?php
$prices = ["Tire" => 100, "Oil" => 21, "Spark Plug" => 6];

echo $prices["Tire"]; // 100
echo $prices["Oil"];  // 21
?>

Instead of numbers, each value has a named key chosen explicitly ("Tire", "Oil", "Spark Plug") using the => arrow syntax. This is the same $prices array used in the foreach with keys example earlier — useful when a plain position number (0, 1, 2) wouldn't mean anything on its own.

Multidimensional Arrays

<?php
$order = [
    ["item" => "Tires", "qty" => 2, "price" => 100],
    ["item" => "Oil", "qty" => 3, "price" => 21],
    ["item" => "Spark Plugs", "qty" => 1, "price" => 6],
];

echo $order[0]["item"]; // Tires
echo $order[1]["qty"];  // 3
?>

An array of arrays — each element of $order is itself an associative array. This is exactly how the order form's data (tires, oil, spark plugs) could be represented as one structured variable instead of three separate ones ($tireqty, $oilqty, $sparkqty).

Multidimensional Array — Indexed Inner Arrays

<?php

$cars = array(
    array("Volvo", 22, 18),
    array("BMW", 15, 13),
    array("Saab", 5, 2),
    array("Land Rover", 17, 15)
);

echo $cars[0][0] . " In stock: " . $cars[0][1] . ", sold: " . $cars[0][2] . ".<br>";

Output:

Volvo In stock: 22, sold: 18.

How this code works, step by step:

  • $cars is the outer array — it holds 4 elements, and each element is itself an array (this is what makes it multidimensional).

  • Each inner array represents one car, with 3 values in a fixed order: [name, quantity in stock, quantity sold]. The first inner array array("Volvo", 22, 18) means: name = "Volvo", in stock = 22, sold = 18.

  • No => keys anywhere, so every level uses plain numeric indexing — the outer array's rows are $cars[0], $cars[1], $cars[2], $cars[3], and each inner array's values sit at position [0], [1], [2].

  • $cars[0] grabs the first row — the whole Volvo array: ["Volvo", 22, 18].

  • $cars[0][0] goes one level deeper into that row and grabs position 0 — "Volvo".

  • $cars[0][1] is position 1 of that row — 22 (in stock).

  • $cars[0][2] is position 2 — 18 (sold).

  • The . operators concatenate it all into one sentence, printed with echo.

So the two bracket pairs mean: the first [row] picks which car, then [position] picks which piece of data about that car. This is the general rule for reading any multidimensional array — one [] per level of nesting.

Same multidimensional array pattern from earlier (like $order), except $cars is an array of indexed arrays this time, not associative — each inner array is accessed purely by position: $cars[0][0] is "Volvo" (row 0, position 0 = the name), $cars[0][1] is 22 (in stock), $cars[0][2] is 18 (sold).

Small gotcha worth noting: the original version of this line ($cars[0][0] . "In stock: ", no leading space) would print VolvoIn stock: 22, sold: 18. — no error, just a missing space, since concatenation never adds spacing on its own. A space needs to be included explicitly in one of the strings, same rule covered back with the order form's "Order Processed" line.

Matrix (2D Array)

<?php
$matrix = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9]
];

echo $matrix[0][0]; // 1 (row 0, column 0)
echo $matrix[1][2]; // 6 (row 1, column 2)
echo $matrix[2][1]; // 8 (row 2, column 1)
?>

A matrix is just a specific use of the multidimensional array covered above — a grid of rows and columns, where each row is itself an array. $matrix[row][column] accesses a specific cell, same double-index pattern as $order[0]["item"] from earlier, just with numeric indexes instead of named keys on the inner array.

Printing the whole matrix with nested for loops (same nested-loop pattern from the for Loop deep dive earlier):

<?php
for ($row = 0; $row < count($matrix); $row++) {
    for ($col = 0; $col < count($matrix[$row]); $col++) {
        echo $matrix[$row][$col] . " ";
    }
    echo "<br>";
}
?>

Output:

1 2 3
4 5 6
7 8 9

The outer loop walks through each row, and the inner loop walks through each column within that row — exactly the same mechanics as the (row, col) nested loop example from earlier, just printing real data from an array instead of coordinate pairs.

Creating Arrays — Two Syntaxes

$a = ["x", "y", "z"];          // short syntax (modern, preferred)
$b = array("x", "y", "z");      // array() syntax (older, still valid)

Both produce the exact same array — [] is just newer, shorter syntax introduced in PHP 5.4; array() is the original way and still works everywhere.

Array Length — count()

<?php
$fruits = ["Apple", "Banana", "Cherry"];
$arrlength = count($fruits); // array length function

for ($x = 0; $x < $arrlength; $x++) {
    echo $fruits[$x];
    echo "<br>";
}
?>

Output:

Apple
Banana
Cherry

count() is the array length function — it returns the number of elements in an array, the same one already used back in the for loop section when looping through $items. Storing it in $arrlength first (rather than calling count($fruits) fresh on every loop check) is a small efficiency habit — it only needs to be calculated once, since the array isn't changing size during the loop.

This is functionally the same as the earlier foreach version of this loop — just written with a for loop and manual indexing instead.

Why this is important: arrays + foreach (from earlier) are the foundation for handling real, structured data — instead of a separate variable for every single piece of information (like the order form currently does with $tireqty, $oilqty, $sparkqty), an array lets related data be grouped, looped over, and scaled to any number of items.

Chapter 12: Managing Systems Support and Security

Phase 5, Systems Support and Security. This phase runs from installation until the system is retired. The analyst's main job here is handling user support requests (help desk, training, user groups).

Four types of maintenance (the most tested list in this chapter):

TypePurposeExampleWho starts it
CorrectiveFix errorsA report prints wrong totalsUsers or IT report a problem
AdaptiveAdd capability for new requirementsSupport a new tax ruleUsers
PerfectiveMake it more efficient or easier to maintainSpeed up a slow query, restructure codeIT staff
PreventiveAvoid future problemsReplace a disk before it failsIT staff

Adaptive and perfective changes together are called enhancements. Reengineering and automated program restructuring are forms of perfective maintenance. Serious corrective errors can be fixed at once; everything else follows standard procedures.

The maintenance process is a mini SDLC: a systems request is submitted and evaluated, then prioritized and scheduled, then investigated, analyzed, designed, developed, tested and implemented. Maintenance teams are analysts and programmers, often rotated between new development and maintenance groups.

Configuration management (CM) controls change requests, versions and documentation. A release methodology bundles noncritical changes into numbered versions, so users are not dealing with constant changes. Baselines are formal reference points: functional (at the start, the system requirements), allocated (after design, the specifications) and product (when the system is operational).

Performance measures: response time (request to reply), bandwidth (data per unit of time), throughput (productive work done) and turnaround time (time to complete a job). Capacity planning uses them to forecast future needs.

Security: the CIA triangle is confidentiality (only authorized access), integrity (no unauthorized changes) and availability (ready when needed). A security policy sets how assets are protected. Risk management identifies, assesses and controls risks to an acceptable level.

Six security levels:

  1. Physical: computer room, servers and desktops (locks, access control, power).

  2. Network: encryption, firewalls, private networks, wireless protection.

  3. Application: services, hardening, permissions, input validation, patches, logs.

  4. File: permissions and encryption for users and groups.

  5. User: identity management, password policy, awareness of social engineering (pretexting, dumpster diving).

  6. Procedural: managerial policies and controls for secure operations.

Common attacks include denial of service (DoS) and distributed DoS, malware, spoofing, sniffing, and privilege escalation.

Backup types:

TypeWhat it copiesRestore
FullEvery fileOne step
DifferentialEverything changed since the last full backupLast full, then last differential
IncrementalOnly files never backed up by any method (fastest)Last full, then every incremental in order
ContinuousAll activity in real time, often with RAIDFast and complete

RAID (redundant array of independent disks) is fault tolerant: one disk can fail without stopping the system. Backups also need a schedule and a retention period.

System obsolescence: a system nears the end of its economic life when maintenance and operating costs rise fast, new technology appears, or new requirements cannot be met. Then the SDLC starts over.

Chapter 10: System Architecture

Phase 3, Systems Design. System architecture turns the logical design into a physical structure of hardware, software and processing methods. The phase ends with the system design specification, after which the project moves to development, needs more design work, or is stopped.

Check before choosing an architecture: enterprise resource planning (ERP, extended to suppliers and customers through supply chain management), initial cost and TCO, scalability, web integration, interfaces to legacy systems, processing options, security, and corporate portals (an entrance to a multifunction website for employees, customers and suppliers).

Architectures, from oldest to newest:

  • Mainframe: the central server does all the processing; terminals only send and display.

  • Distributed / file server: clients connected in LANs and WANs; in a file server design, the client does all the processing.

  • Client/server: work is split. The client handles the user interface (entry, queries, screens); the server stores data and manages the database; application logic is divided between them. More scalable and flexible than file server designs.

  • Internet-based and cloud: remote servers handle processing; the Internet replaces private networks.

Fat vs. thin client:

Fat (thick) clientThin client
Where the logic runsMostly on the clientMostly on the server
TCOHigher (client hardware, updates)Lower
DevelopmentSimpler, resembles file server designMore server work

Two-tier vs. three-tier (n-tier): in two-tier, the interface is on the client and data is on the server, with logic on either side. Three-tier adds a middle layer, the application server, which holds the business logic and translates client requests into data commands. Middleware connects dissimilar applications so they can pass data.

Processing methods: online processing handles transactions as they happen and updates files right away (the most common). Batch processing runs groups of transactions on a schedule (reports, payroll). Many systems use both.

Networks: the OSI model has seven layers: physical, data link, network, transport, session, presentation, application (bottom to top). Five topologies:

TopologyLayout
HierarchicalA tree, usually controlled by a mainframe
BusAll nodes on one single-line path
RingNodes in a circle, data passing around it
StarAll nodes connect to a central switch
MeshEvery node connects to every other node (most redundant)

Wireless (WLAN) uses IEEE 802.11 standards; 802.11ac uses MIMO for more speed and range. WLANs run in two topologies: BSS (clients through one access point) and ESS (several access points). Downsides are interference and security.

Likely test points

  • Client/server: what the client does vs. what the server does.

  • Fat vs. thin client, and two-tier vs. three-tier (what the application server does).

  • Online vs. batch processing.

  • Name the five topologies and the seven OSI layers in order.

  • The system design specification is the deliverable of Phase 3.

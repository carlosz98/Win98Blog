HTML concepts used in the project

1. The page skeleton

Every page starts the same way. <!DOCTYPE html> tells the browser this is HTML5. <html lang="en"> wraps everything and declares the language. <head> holds information about the page; <body> holds what you see.

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Recipes Page</title>
    <link rel="stylesheet" href="styles.css">
</head>
<body>
    ...
</body>
</html>

  • <meta charset="UTF-8"> makes characters like the copyright sign display correctly.

  • <meta name="viewport" ...> makes phones use the real screen width instead of zooming out.

  • <title> is the text on the browser tab and in bookmarks; it is not shown on the page.

  • <link rel="stylesheet" href="..."> connects an external CSS file.

2. Semantic layout elements (index.html)

Semantic tags describe what a part of the page is, not how it looks. Screen readers and search engines use them.

TagMeaningIn your home page
<header>Intro or banner areaThe gray bar with the h1 "Recipes"
<nav>Main navigation linksThe Oatmeal / Pancakes / Dinner / Snacks / Contact bar
<main>The main content, once per pageThe 5 content boxes
<section>A themed group of content, usually with a headingrelated-recipes, recipe-description, etc.
<footer>Closing info (copyright, contact)"© 2024 Recipes Page"
<div>Generic box with no meaning.container on the recipe pages

Rule of thumb: use a semantic tag when one fits, and <div> only when you just need a box to style.

3. Headings

Headings go from <h1> (most important) to <h6>. The home page has one <h1> and an <h2> per section. The recipe pages start at <h2> and use <h3> for "Ingredients" and "Directions". Best practice is one <h1> per page and no skipped levels.

4. Lists

<ul>
    <li>1 cup rolled oats</li>
    <li>1.5 cups milk</li>
</ul>

  • <ul> = unordered (bullets), for items where order does not matter, like ingredients.

  • <ol> = ordered (numbers), for steps. The home page types "1.", "2.", "3." by hand with <br>; an <ol> does this for you.

  • <li> = one list item, and it must sit directly inside a <ul> or <ol>.

  • The nav bar is also a <ul>: a menu is a list of links, and CSS turns it sideways.

5. Links and paths

<a href="oatmeal.html">Oatmeal</a>
<a href="index.html">Back to Home</a>

<a> makes a hyperlink and href is where it goes. These are relative paths: they are resolved from the current file's folder. An absolute URL includes the protocol and domain, like https://example.com/page.html. A link can also open an email (href="mailto:...") or a phone call (href="tel:...").

6. Images

<img src="images/avocado.jpg" alt="Related Recipe 1">

  • <img> is a void (empty) element: it has no closing tag.

  • src is the file path; images/ means "the images folder next to this page".

  • alt is the text read by screen readers and shown if the image fails to load. It should describe the picture ("Avocado and cucumber salad"), not just number it.

7. Text elements and entities

  • <p> is a paragraph; the browser adds space around it.

  • <br> forces a line break inside text. It is also a void element. Use it for line breaks inside one thing (an address), not to build lists.

  • &copy; is an HTML entity that displays ©. Others: &amp; (&), &lt; (<), &gt; (>), &nbsp; (non-breaking space).

8. Attributes: class, alt, href, lang

Attributes go inside the opening tag as name="value". class="container" gives an element a name that CSS can target with .container. A class can be reused on many elements; an id must be unique on the page.

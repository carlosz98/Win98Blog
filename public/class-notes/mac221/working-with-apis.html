Working with APIs

An API (Application Programming Interface) lets your app talk to an outside service, which usually sends back JSON. The class pattern is always the same four pieces: a Codable model, a service class that fetches, @Published to hold the result, and a view that calls fetch in .onAppear.

PieceWhat it does
URLSessionSwift's API for making HTTP requests
JSONDecoderTurns JSON data into Swift types
CodableProtocol that makes a type encodable and decodable
ObservableObject + @PublishedUpdate the UI when the data arrives

1. Model

struct Product: Identifiable, Codable {
    let id: Int
    let name: String
    let price: Int
    let imageUrl: String
}

2. Service class

class ProductService: ObservableObject {
    @Published var products: [Product] = []

    func fetchProducts() {
        guard let url = URL(string: "https://example.com/products.json") else { return }
        URLSession.shared.dataTask(with: url) { data, response, error in
            if let data = data {
                if let result = try? JSONDecoder().decode([Product].self, from: data) {
                    DispatchQueue.main.async {
                        self.products = result   // UI updates must happen on the main thread
                    }
                }
            }
        }.resume()   // without resume() the request never starts
    }
}

3. View

struct ContentView: View {
    @ObservedObject var service = ProductService()

    var body: some View {
        List(service.products) { product in
            VStack(alignment: .leading) {
                Text(product.name).bold()
                Text("$\(product.price)")
            }
        }
        .onAppear { service.fetchProducts() }
    }
}

Remember these details:

  • The model needs Identifiable so List can tell rows apart, and Codable so JSONDecoder can build it. The property names must match the JSON keys.

  • [Product].self means "decode an array of Product".

  • dataTask runs in the background, so the result is assigned inside DispatchQueue.main.async.

  • .resume() is what actually starts the request.

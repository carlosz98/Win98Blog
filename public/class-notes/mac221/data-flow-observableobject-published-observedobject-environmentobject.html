Data flow: ObservableObject, @Published, @ObservedObject, @EnvironmentObject

An ObservableObject is a class that tells SwiftUI when its data changes, so every view watching it redraws. It comes from the Combine framework, Apple's toolkit for asynchronous, event-driven code. Think of it as a messenger between your data and the screen.

WrapperUsed onWho owns the dataUse it when
@StateA simple value (Bool, Int, String) in a viewThe view itselfData only this view needs
@BindingA property in a child viewThe parent's @StateA child needs to read and change the parent's value
@PublishedA property inside an ObservableObject classThe classThat property should trigger redraws when it changes
@ObservedObjectAn ObservableObject in a viewWhoever created itThe view watches an object passed in or created there
@StateObjectAn ObservableObject the view createsThe view (kept across redraws)The view creates and owns the object (newer and safer than @ObservedObject for this)
@EnvironmentObjectAn ObservableObject shared app-wideInjected once near the topMany views need the same object without passing it down by hand

Example 1: ObservableObject + @Published + @ObservedObject

class UserData: ObservableObject {                // must be a class
    @Published var username: String = "Guest"     // changes notify the views
}

struct ContentView: View {
    @ObservedObject var userData = UserData()

    var body: some View {
        VStack {
            Text("Welcome, \(userData.username)!")
            TextField("Enter your name", text: $userData.username)   // $ = binding to the property
                .padding()
        }
    }
}

Typing "MAC221" in the field changes username, which updates the Text to "Welcome, MAC221!" right away.

Example 2: methods and a computed property

class UserData: ObservableObject {
    @Published var username: String = "Guest"
    @Published var age: Int = 25

    var canVote: Bool { age >= 18 }    // computed property, recalculated each time

    func increaseAge() { age += 1 }
    func decreaseAge() { age -= 1 }
}

struct ContentView: View {
    @EnvironmentObject var userData: UserData     // no "= UserData()": it's handed in

    var body: some View {
        VStack {
            Text("Welcome, \(userData.username)!")
            Text("Age: \(userData.age)")
            Text("Can Vote: \(userData.canVote ? "Yes" : "No")")
            HStack {
                Button("Increase Age") { userData.increaseAge() }
                Button("Decrease Age") { userData.decreaseAge() }
            }
        }
    }
}

Injecting an EnvironmentObject

Create it once in the @main App struct and attach it with .environmentObject(...). Every view below can then read it with @EnvironmentObject.

@main
struct Nov28_1App: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
                .environmentObject(UserData())    // inject here
        }
    }
}

Older projects (Xcode 11) did the same thing in SceneDelegate.swift with UIHostingController(rootView: ContentView().environmentObject(UserData())).

Common mistake: if a view uses @EnvironmentObject but nothing injected it, the app crashes at runtime. Previews need it too: ContentView().environmentObject(UserData()).

Chapter 1: Introduction to Linux

Linux is a free, open source, multiuser and multitasking OS built on Linus Torvalds' 1991 kernel and shipped in many distributions.

Key concepts

  • Hardware = physical parts (CPU, RAM, disks, cards, ports, motherboard). Software = instructions that make the hardware work.

  • Applications are what users interact with; the OS controls the hardware. A device driver tells the OS how to use one device. The user interface is a command line or a GUI. System services handle printing, scheduling and network access.

  • Kernel = the core of Linux, written almost entirely in C, common to every distro.

  • Kernel version = major.minor.revision. Production kernels are tested and stable; developmental kernels are not.

  • Open Source Software (OSS): source code is free to get and change. Bugs get fixed fast and features evolve quickly.

  • GPL (GNU Public License, from the Free Software Foundation): source must stay free, and modified code must also be shared freely. The Artistic license keeps the source free but gives the original author some control.

  • Closed source = no source code, usually paid (commercial). Freeware = closed but free. Shareware = free at first, pay later.

  • Advantages: risk reduction, meets business needs, stability and security, runs on many platforms (x86/x64, ARM, mainframe, PowerPC...), easy to customize, easy support (HOWTOs from the LDP, FAQs, newsgroups, LUGs), lower TCO (total cost of ownership).

  • History: UNIX grew out of MULTICS, was rewritten in C, and split into flavors (BSD, HP-UX, AIX, macOS). Richard Stallman founded the FSF and the GNU project, which produced the GPL. Linus Torvalds wrote Linux in 1991.

  • Hacker = learns by experimenting. Cracker = breaks in for gain or damage.

  • Distribution = kernel + libraries + add-on software (Red Hat, Fedora, openSUSE, Debian, Ubuntu, Mint, Arch, Gentoo).

  • GUI = X Windows + a window manager + a desktop environment. The two main desktops are GNOME and KDE.

  • Package manager installs and maintains software; RPM is the most widely supported. A tarball is a compressed archive that is harder to manage.

  • Uses: Internet servers (web, DNS, DHCP, mail, FTP, firewall), file and print servers (Samba), application servers (databases/DBMS), cloud (SaaS, PaaS, IaaS), supercomputers (Beowulf clusters with MPI), workstations, cybersecurity, mobile (Android).

Likely test points

  • GPL rules; open source vs closed source vs freeware vs shareware.

  • Who did what: Stallman (FSF, GNU, GPL) and Torvalds (Linux, 1991).

  • Kernel is written in C; major.minor.revision numbering.

  • GNOME vs KDE; X Windows is the core of the GUI.

  • SaaS / PaaS / IaaS; Beowulf clustering; Samba for file sharing.

Disk Management

Filesystems must be mounted to a directory before use, checked with fsck when unmounted, and watched with df (space per filesystem) and du (space per directory).

Key concepts

  • Root filesystem is mounted on / at boot and holds most OS files.

  • mount attaches a device to a mount point directory; with no arguments it lists what's mounted. umount (no "n") detaches it.

  • /etc/fstab lists filesystems to mount automatically at boot.

  • Filesystem corruption usually comes from an improper shutdown. Syncing = writing data from RAM to disk. Bad blocks = unusable areas of the disk.

  • fsck checks a filesystem for errors. The filesystem must be unmounted first; -f forces a full check.

  • Monitor mounted filesystems for errors, disk space and inode usage. Clear out old log files to free space.

  • df = disk free: space used and available per mounted filesystem (partition). Give it a file and it shows only the filesystem that file lives on.

  • du = directory usage: size of a directory and its contents (KB by default).

Commands

mount                         # list mounted filesystems
mount /dev/sdb1 /mnt/usb      # mount a device
umount /mnt/usb               # unmount it
cat /etc/fstab                # boot-time mounts
fsck -f /dev/sdb1             # full check (unmount first!)
df -h                         # free space on all filesystems, readable
df -h /home/john/house2       # just the filesystem holding that file
df -i                         # inode usage
du -h /home/john/projects     # size of each subdirectory
du -ah /home/john/projects    # every file and directory
du -sh /home/john/projects    # one total

Likely test points

  • df vs du (filesystem free space vs directory size).

  • -h human readable, -s summary, -a all files.

  • fsck needs the filesystem unmounted.

  • /etc/fstab mounts at boot; the command is umount.

Lecture 8: Polymorphism

Polymorphism ("many forms") lets one interface perform different actions depending on the object; C++ does it at compile time (overloading) or at run time (virtual functions).

Compile-time (static binding)Runtime (dynamic binding / late binding)
HowFunction overloading, operator overloadingVirtual functions + inheritance + overriding
DecidedWhen the code compilesWhile the program runs, by the object's real type
NeedsDifferent parameter number or typesBase class pointer or reference to a derived object

Benefits from the slides: flexibility and maintainability, reusability, and interchangeability (related objects can be treated as their common base type).

Operator overloading: Number operator+(const Number& other)

  • Number: the return type; num1 + num2 produces a new Number.

  • operator+: the special function name for +.

  • const: other is read-only inside the function.

  • Number&: pass by reference so no copy is made.

  • other: the right-hand operand. In num1 + num2, num1 is this and num2 is other.

class Number {
    int value;
public:
    Number(int v) : value(v) {}
    Number operator+(const Number& other) {
        return Number(value + other.value);
    }
    void display() { cout << "Value: " << value << "\n"; }
};
// Number result = Number(10) + Number(20);  result.display();  // Value: 30

Runtime polymorphism: the Animal example from class

class Animal {
public:
    virtual void sound() { cout << "Animal makes a sound\n"; }
    void type()          { cout << "General Animal\n"; }   // NOT virtual
};
class Dog : public Animal {
public:
    void sound() override { cout << "Dog barks\n"; }
    void type()           { cout << "Domestic Dog\n"; }
};
class Cat : public Animal {
public:
    void sound() override { cout << "Cat meows\n"; }
};

int main() {
    Dog dog; Cat cat;
    Animal* animalPtr = &dog;
    animalPtr->sound();   // Dog barks       (virtual: uses the real object)
    animalPtr->type();    // General Animal  (not virtual: uses the pointer type)
    animalPtr = &cat;
    animalPtr->sound();   // Cat meows
    animalPtr->type();    // General Animal
    return 0;
}

Common mistakes

  • Forgetting virtual in the base class. The call then uses the pointer's type, so you get the base version.

  • Calling through an object by value (Animal a = dog; a.sound();). The object is sliced to an Animal, so no polymorphism; use a pointer or reference.

  • Overloading by return type only (not allowed).

  • override is optional, but it makes the compiler check that you really are overriding a virtual function.

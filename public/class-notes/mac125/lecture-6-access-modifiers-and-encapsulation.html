Lecture 6: Access Modifiers and Encapsulation

Access modifiers (public, private, protected) decide who can touch a class member, and they are the tool C++ uses to achieve encapsulation.

ModifierSame classDerived classOutside codeTypical use
publicYesYesYesThe class's interface: constructors, getters, setters, other methods
protectedYesYesNoData subclasses need but the public shouldn't see
privateYesNoNoSensitive data; the default in a class

Encapsulation

  • Definition: wrapping data and the methods that work on it into one unit (the class) and hiding the internal state.

  • Purpose: protect the object's integrity by preventing unauthorized access and misuse.

  • Benefits: data hiding, a simplified interface, and easier maintenance (the inside can change without breaking code that uses the class).

  • How: make attributes private, then provide public get and set methods. The setter can validate input.

#include <iostream>
using namespace std;

class Employee {
private:
    int salary;                     // hidden from outside code
protected:
    string department;              // visible to subclasses
public:
    void setSalary(int s) {         // setter with validation
        if (s >= 0) salary = s;
    }
    int getSalary() const {         // getter
        return salary;
    }
};

int main() {
    Employee e;
    e.setSalary(50000);
    cout << e.getSalary() << "\n";   // 50000
    // e.salary = 10;               // ERROR: salary is private
    return 0;
}

Common mistakes

  • Thinking a derived class can read a base class's private members. It can't; that is what protected is for.

  • Forgetting that class members are private by default (struct members are public by default).

  • Writing setters that just assign without checking, which gives up the main benefit of encapsulation.

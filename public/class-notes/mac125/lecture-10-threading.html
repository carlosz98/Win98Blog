Lecture 10: Threading

A thread is the smallest unit of execution in a process; threads in one process share memory but run independently, and C++11's <thread> header is the standard way to create them.

  • Concurrency: tasks make progress in overlapping time, not necessarily at the same instant.

  • Parallelism: tasks truly run at the same time, usually on multiple CPU cores.

  • std::thread t1(func, args...); creates and starts a thread.

  • t1.join(); makes the caller wait for the thread to finish.

  • t1.detach(); lets it run on its own in the background; it can't be joined afterwards.

Five ways to pass arguments

WaySyntaxNote
By valuethread t(printNumber, 42);Safe (own copy), slow for big data
By referencethread t(modifyValue, std::ref(value));Must use std::ref, or it copies
By movethread t(processString, std::move(msg));No deep copy; msg is empty afterwards
Lambdathread t([x, y]() { ... });Capture by value [=] or by reference [&]
std::bindauto task = bind(multiply, 4, 5); thread t(task);Pre-binds fixed arguments (<functional>)
#include <iostream>
#include <thread>
using namespace std;

void modifyValue(int& num) { num += 10; }

int main() {
    int value = 5;
    thread t1(modifyValue, ref(value));   // pass by reference
    t1.join();                            // wait before reading value
    cout << "Modified Value: " << value << "\n";  // 15

    int x = 10, y = 20;
    thread t2([x, y]() { cout << "Sum: " << x + y << "\n"; });
    t2.join();
    return 0;
}

Detach safely. A detached thread can outlive main()'s local variables. Passing a local by std::ref to a detached thread is undefined behavior (crash or corrupted memory). Fixes from class: allocate with new and delete inside the thread, or better, use std::shared_ptr / std::unique_ptr so cleanup is automatic.

void printMsg(string* m) {
    this_thread::sleep_for(chrono::seconds(1));
    cout << "Message: " << *m << "\n";
    delete m;                              // the thread frees it
}
// in main:
thread t(printMsg, new string("Hello, Thread!"));
t.detach();

Use detach() for independent background work (logging, monitoring, network). Use join() when you need the result or the thread touches shared data.

Common mistakes

  • Never calling join() or detach(). A std::thread destroyed while still joinable calls std::terminate and the program aborts.

  • Passing a reference parameter without std::ref.

  • Using a variable after std::move sent it into a thread.

  • Detached threads using local variables by reference.
